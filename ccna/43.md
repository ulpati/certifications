## Understanding Network Address Translation  

### IPv4 Address Conservation and the Role of NAT  

As IPv4 address exhaustion became a concern, several key technologies helped extend its usability:  

| **Feature** | **Primary Benefit** |
|--------------|----------------------|
| **CIDR (Classless Inter-Domain Routing)** | Allows more precise allocation of IPv4 address blocks and efficient route aggregation across global networks. |
| **NAT (Network Address Translation)** | Enables thousands of TCP/UDP sessions (around 65,000) to be supported using a single public IPv4 address. |
| **Private IP Networks** | Supports the use of internal private addresses while connecting to the public Internet via NAT. |

---

## Inside Source NAT  

Inside Source NAT is the most common NAT configuration used at the **enterprise edge**. It enables devices with **private IP addresses** to communicate with external hosts across the Internet.  

The NAT process replaces the **source IP address** in outgoing packets with a valid **public IP address**. On return traffic, NAT translates the **destination IP** back to the corresponding private address.  

There are **three main variants** of inside source NAT:  
- **Static NAT**  
- **Dynamic NAT**  
- **Port Address Translation (PAT)** — also called *NAT Overload*  

---

## Static NAT  

**Static NAT** establishes a **permanent one-to-one mapping** between a private and a public IP address.  

This type of NAT requires manual configuration of NAT table entries using the command:  
```bash
ip nat inside source static <private_address> <public_address>
````

While static NAT is simple and predictable, it **does not conserve public IP addresses**, since each internal address requires a dedicated external one.

---

## Inside Local vs. Inside Global Addresses

Cisco NAT terminology distinguishes between internal and external perspectives:

| **Term**                  | **Definition**                                                                                                                                         |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Inside Local Address**  | The private IP address assigned to a host within the internal network. This address appears in the host’s configuration and is typically a private IP. |
| **Inside Global Address** | The public IP address assigned by NAT to represent the internal host on the Internet. This address is found in the NAT table, not on the host itself.  |

In this context:

* “Inside” refers to the **enterprise or internal** network.
* “Outside” refers to the **public Internet**.

---

## Dynamic NAT

**Dynamic NAT** also performs one-to-one translations, but instead of static configuration, it **dynamically assigns public addresses from a predefined pool**.

When an internal device initiates traffic to the Internet, the router selects an available public IP from the pool and creates a NAT table entry. The mapping remains active while traffic continues to flow, and times out when idle.

If the pool is exhausted and a new connection request arrives, NAT drops the packet until an entry times out.

Key security feature:

* **Dynamic NAT entries are created only by traffic originating from the inside network**, reducing exposure to unsolicited inbound connections.

**Useful commands:**

```bash
clear ip nat translation *
```

(Manually clears all dynamic NAT entries.)

---

## Port Address Translation (PAT) – NAT Overload

**Port Address Translation (PAT)** allows multiple private hosts to share **a single public IP address** by differentiating connections using **port numbers**.

PAT translates both the **IP address** and **port number**, enabling thousands of unique connections per public address.

When a new outbound session is initiated, the router records the **inside local IP and port** and associates them with a **unique combination of public IP and port**.

Since port numbers are 16 bits long, PAT can theoretically support up to **65,536 concurrent connections per public IP**.

This method efficiently conserves public addresses while maintaining session integrity for each internal host.

## Configuring and Troubleshooting NAT

### Static NAT Configuration

1. Identify internal and external interfaces:

   ```bash
   interface <type/number>
   ip nat inside
   interface <type/number>
   ip nat outside
   ```
2. Configure the IP subnet that includes the inside global address.
3. Define static mappings:

   ```bash
   ip nat inside source static <inside-local> <inside-global>
   ```
4. Verify NAT operation:

   ```bash
   show ip nat translations
   show ip nat statistics
   ```

---

### Dynamic NAT Configuration

Dynamic NAT uses **ACLs** and **address pools** to manage translations dynamically.

**Configuration steps:**

1. Define inside and outside interfaces.
2. Create an **ACL** permitting traffic to be translated:

   ```bash
   access-list <number> permit <source> <wildcard>
   ```
3. Define a **pool of public addresses**:

   ```bash
   ip nat pool <name> <start> <end> netmask <mask>
   ```
4. Bind the ACL to the pool:

   ```bash
   ip nat inside source list <acl-number> pool <pool-name>
   ```

When inside hosts send traffic that matches the ACL, NAT automatically allocates a public IP from the pool.

---

### PAT (NAT Overload) Configuration

There are two common PAT configurations:

1. **Using a pool of addresses:**
   Add the `overload` keyword to the dynamic NAT command:

   ```bash
   ip nat inside source list <acl-number> pool <pool-name> overload
   ```

2. **Using a single public interface address:**

   ```bash
   ip nat inside source list <acl-number> interface <type/number> overload
   ```

This approach is widely used for small to medium networks that have limited public IP resources.

---

## Troubleshooting NAT

Most NAT issues arise from **incorrect interface designations** or **ACL misconfigurations**.

To diagnose NAT behavior:

* Verify current translations:

  ```bash
  show ip nat translations
  ```
* Check statistics and activity:

  ```bash
  show ip nat statistics
  ```
* Ensure inside/outside interfaces are properly defined.

If connections fail, confirm that:

* The ACL matches outbound traffic correctly.
* The NAT pool has available addresses.
* The correct overload option is used when required.
