APIs (Application Programming Interfaces) allow software components on different systems to communicate and exchange information. In modern network automation, one of the most widely used API models is **REST** (Representational State Transfer), which follows a set of architectural principles designed for scalability, simplicity, and flexibility.

---

## REST-Based APIs

Applications use APIs to share data, coordinate tasks, and interact with external systems. REST is highlighted in the CCNA curriculum because it has become a foundation for network programmability.

To securely interact with APIs, several authentication mechanisms exist, including:

- API keys  
- JSON Web Tokens (JWT)  
- TLS/SSL client certificates  
- Basic authentication  
- Session cookies  

### What Makes an API RESTful?

REST APIs follow six essential principles:

1. **Client/Server Architecture**  
2. **Stateless Communication**  
3. **Defined Cache Behavior**  
4. **Uniform Interface**  
5. **Layered Structure**  
6. **Optional Code-on-Demand**

---

### Client/Server Architecture

A developer designs and deploys a REST API, which acts as the **server**. Any external application that interacts with it becomes the **client**, sending requests and receiving structured responses.

### Stateless Operation

REST requires the server to remain stateless. This means the server does not store session data from previous requests. Instead, the client must include all necessary context each time it sends a request.

### Cacheable Resources

Every REST resource must clearly indicate whether it is cacheable. If a resource is marked as cacheable, the client can store it temporarily to improve performance. Cacheable items also include a validity period, after which the client must request a fresh version.

---

## REST APIs and HTTP

RESTful APIs commonly use **HTTP** because its design aligns naturally with REST principles: client/server separation, statelessness, and cache control through HTTP headers.

### CRUD Operations and HTTP Methods

Most applications rely on four core operations known as **CRUD**:

- **Create**  
- **Read**  
- **Update**  
- **Delete**

REST maps these actions to specific HTTP verbs:

| Action | CRUD Term | HTTP Verb |
|--------|-----------|-----------|
| Create new resources | Create | POST |
| Retrieve data | Read | GET |
| Modify existing data | Update | PUT, PATCH |
| Remove data | Delete | DELETE |

---

## Identifying Resources with URIs

REST uses **URIs (Uniform Resource Identifiers)** to specify which resource an HTTP request interacts with. A typical URI contains:

- **Scheme/Protocol** — e.g., `https://`  
- **Authority** — Hostname or IP address (with optional port)  
- **Path** — Points to a specific resource  
- **Query Parameters** — Key/value pairs introduced after `?` to refine the request  

Example:  
`https://api.example.com/users?id=23`

## Data Serialization and JSON

### Why APIs Need a Data Model

APIs exchange structured information. Data serialization languages convert in-memory variables into text formats that can be transmitted over a network or saved in files. On the server side:

1. Internal variables are prepared for output.  
2. The server converts them into a chosen data format.  
3. The serialized text is sent to the client.  
4. The client converts the text back into local variables.

This process lets clients and servers share complex data structures regardless of programming language.

---

## Common Data Serialization Languages

### JSON (JavaScript Object Notation)

JSON balances readability with structured formatting, making it ideal for REST APIs. JSON can be parsed easily by most programming languages, especially when working with automation tools.

### XML (eXtensible Markup Language)

XML was originally designed for marking up web content but evolved into a powerful data serialization format. It uses opening/closing tags similar to HTML and emphasizes structured, machine-readable data. While heavier than JSON, XML remains common in many enterprise systems.

### YAML (YAML Ain't Markup Language)

YAML avoids markup tags and focuses on concise, human-friendly structure definitions. Tools like **Ansible** prefer YAML for configuration files due to its readability.

### Summary Table

| Acronym | Name | Purpose | Common Use |
|---------|------|----------|-------------|
| JSON | JavaScript Object Notation | General data modeling and serialization | REST APIs |
| XML | eXtensible Markup Language | Data markup and structural modeling | APIs, web pages |
| YAML | YAML Ain't Markup Language | Clean and simple data modeling | Automation tools (e.g., Ansible) |

## Understanding JSON Structure

### Key-Value Pairs

JSON is built on **key:value** pairs:

- **Key** — A name in double quotes  
- **Value** — A piece of data (string, number, object, array, etc.)  
- Pairs are separated by commas  
- Each key must be unique within an object  

Example:
```json
{
  "name": "Router1",
  "id": 42
}
````

### JSON Objects `{}` and Arrays `[]`

JSON uses:

* **Objects `{}`** — collections of key:value pairs
* **Arrays `[]`** — ordered lists of values

Values inside arrays must follow JSON’s formatting rules.

Python—commonly used in networking—maps JSON structures to:

* **Objects → dictionaries**
* **Arrays → lists**

JSON also supports unlimited nesting, allowing objects and arrays within each other.

### Minified vs. Pretty JSON

JSON can be formatted in two ways:

* **Pretty (beautified)** — spaced and indented for readability
* **Minified (raw)** — compact format without extra whitespace

APIs typically send minified JSON to reduce bandwidth, while tools and editors display pretty JSON for easier understanding.
