## Analyzing Subnetting and Addressing Needs

### Rules Defining Subnet Boundaries
- **Devices within the same subnet** communicate directly without passing through a router.  
- **Devices in different subnets** must communicate through at least one router, which separates the networks.

### Determining the Number of Subnets
When designing networks (as per CCNA scope), plan for **one subnet per VLAN**, **point-to-point serial link**, and **Ethernet WAN connection**.  
This ensures proper segmentation, performance, and fault isolation.

---

## One Size Subnet Fits All – Or Not?

A subnet’s **size** refers to the number of usable IP addresses it contains. Engineers can design networks using **a single subnet size** for simplicity or **multiple subnet sizes** for flexibility and efficiency.

### Defining the Size of a Subnet
Each subnet is assigned a **subnet mask**, which determines how many bits are reserved for host addressing.  
If a mask defines `H` host bits, the total number of possible host addresses is: `2^H - 2`


(The subtraction of 2 accounts for the network and broadcast addresses.)

Every IPv4 address consists of three parts:
- **Network**
- **Subnet**
- **Host**

---

### One Size Subnet Fits All
When a single mask is used for all subnets, it must provide **enough host addresses** for the largest subnet.  
That means choosing a subnet mask where `2^H - 2` exceeds the number of hosts required in the largest network.

**Pros:** Simplicity in management and predictability.  
**Cons:** Inefficient IP utilization — for example, using a large subnet mask for small WAN links that need only two IP addresses.

---

### Multiple Subnet Sizes (Variable-Length Subnet Masks - VLSM)
With **VLSM**, different subnets use masks of varying lengths, depending on size requirements.  
Each subnet still follows the same formula:  
`2^H - 2`, where `H` equals the number of host bits for that specific subnet.

**Example:**  
For a WAN link, `H = 2` results in `2^2 - 2 = 2` usable IP addresses — perfect for point-to-point connections.

## Making Design Choices

### Choosing a Classful Network

#### Public IP Networks
In the early Internet, any company connecting online required a **registered public IP network** — either class A, B, or C. These addresses were globally unique and assigned by regulatory authorities.

#### The Exhaustion of Public IP Space
As the Internet expanded, public IPv4 addresses began to run out. Several solutions were introduced to address this problem:
- **IPv6**: A new version of IP with 128-bit addresses (compared to IPv4’s 32-bit).  
- **CIDR (Classless Inter-Domain Routing):** Allowed more efficient allocation by assigning smaller, custom-sized address blocks instead of entire class networks.  
- **NAT (Network Address Translation):** Enabled organizations to use **private IP addresses** internally while sharing a limited pool of public IPs for external communication.

---

#### Private IP Networks
NAT uses **private IP ranges**, defined as follows:

| Class | Private IP Range | Number of Networks |
|:------|:-----------------|:-------------------|
| A | 10.0.0.0 | 1 |
| B | 172.16.0.0 – 172.31.0.0 | 16 |
| C | 192.168.0.0 – 192.168.255.0 | 256 |

Private networks help reduce global IP consumption and improve scalability. They also:
- Prevent address conflicts by isolating internal networks.
- Delay IPv4 exhaustion.
- Simplify routing tables in the global Internet backbone.

## Choosing the Mask

### Classful IP Networks Before Subnetting
Originally, IPv4 addresses were divided into classes:

| Class | Network Bits (N) | Host Bits (H) |
|:------|:----------------:|:--------------:|
| A | 8 | 24 |
| B | 16 | 16 |
| C | 24 | 8 |

In these **unsubnetted** networks, all addresses share the same **network portion**, while the **host portion** uniquely identifies each device.

---

### Choosing Subnet and Host Bits
To design efficient subnets:
1. Determine the **number of required subnets**.  
2. Determine the **maximum hosts per subnet**.

Then apply these formulas:
- Number of subnets: `2^S` (S = subnet bits borrowed from host portion).  
- Hosts per subnet: `2^H - 2` (H = remaining host bits).

Ensure that both values meet or exceed the design requirements.  
> **Note:** The `2^S` rule applies only when using a single subnet mask across a classful network.

---

### Masks and Mask Formats
A **subnet mask** is a 32-bit binary number that separates the network and host portions.  
It consists of:
- `1`s on the left (for network and subnet bits)
- `0`s on the right (for host bits)

Masks can be written in two formats:
- **Dotted-decimal notation (DDN):** e.g., `255.255.255.0`
- **Prefix notation:** e.g., `/24`

Both represent the same concept — the division between network and host portions.
