## System Message Logging (Syslog)

### Sending Messages in Real Time to Current Users  

By default, Cisco IOS displays log messages on the **console** for all severity levels using the command:  
```
logging console
```

However, for **Telnet** and **SSH** sessions, message logging requires a two-step setup:

1. Enable message logging globally for remote sessions:

   ```
   logging monitor
   ```
2. Within the user's session, run the command:

   ```
   terminal monitor
   ```

This tells the router or switch to send log messages to the user’s current terminal session in real time.

---

## Storing Log Messages for Later Review

IOS can also **store log messages in RAM** using the buffered logging feature:

```
logging buffered
```

Users can then view the stored messages at any time with:

```
show logging
```

In production environments, it's common practice to **centralize log storage** by sending log messages to an external **Syslog server** via UDP:

```
logging host <address or hostname>
```

---

### Syslog Message Severity Levels

Each log message is assigned a **severity level** by IOS — the lower the number, the higher the severity.

| Keyword       | Level | Description               | Category  |
| ------------- | ----- | ------------------------- | --------- |
| Emergency     | 0     | System unusable           | Severe    |
| Alert         | 1     | Immediate action required | Severe    |
| Critical      | 2     | Critical event            | Impactful |
| Error         | 3     | Error event               | Impactful |
| Warning       | 4     | Warning event             | Impactful |
| Notification  | 5     | Normal notification       | Normal    |
| Informational | 6     | Informational message     | Normal    |
| Debug         | 7     | Debug-level message       | Debug     |

---

### Configuring and Verifying System Logging

| Logging Type | Enable Logging           | Set Severity Level         |
| ------------ | ------------------------ | -------------------------- |
| Console      | `logging console`        | `logging console <level>`  |
| Monitor      | `logging monitor`        | `logging monitor <level>`  |
| Buffered     | `logging buffered`       | `logging buffered <level>` |
| Syslog       | `logging host <address>` | `logging trap <level>`     |

When you configure a severity level, the device logs messages of that level **and all higher-severity events**.

To review the configuration and stored messages, use:

```
show logging
```

## Network Time Protocol (NTP)

The **Network Time Protocol (NTP)** allows network devices to synchronize their internal clocks. This synchronization ensures consistent timestamps in logs, authentication mechanisms, and time-sensitive processes.

NTP devices exchange time data continuously, comparing timestamps and adjusting their local clocks until synchronization is achieved.

---

### Setting the Time and Time Zone

To manually configure the time and time zone on a Cisco device:

```
clock timezone EST -5
clock summer-time EDT recurring
clock set 12:32:00 19 January 2023
```

You can confirm the device's clock settings with:

```
show clock
```

---

### Basic NTP Configuration

NTP operates in a **client-server** model where servers provide time updates to clients.

Cisco provides two main commands for NTP configuration:

* **NTP Master Mode** (acts as a local NTP server):

  ```
  ntp master <stratum-level>
  ```

  The device uses its internal clock as the reference time source.

* **NTP Client/Server Mode:**

  ```
  ntp server <address or hostname>
  ```

  The device synchronizes its time with another NTP server and can then provide time to downstream clients.

To verify NTP status and synchronization details:

```
show ntp status
show ntp associations
```

---

### NTP Reference Clock and Stratum

Each NTP device is assigned a **stratum level**, indicating how far it is from an authoritative time source:

* **Stratum 0:** Highly accurate reference clock (e.g., atomic clock or GPS).
* **Stratum 1:** Device directly connected to a Stratum 0 source.
* **Stratum 2–15:** Devices further away in the NTP hierarchy.
* **Stratum 16:** Unusable or unsynchronized clock.

By default, Cisco devices use a **stratum level of 8** for their internal clock, but this can be configured from 1 to 15. The higher the number, the less accurate the source is considered.

## Analyzing Network Topology Using CDP and LLDP

### Discovering Devices with CDP

**Cisco Discovery Protocol (CDP)** is a Cisco-proprietary protocol that allows routers and switches to learn basic information about directly connected Cisco devices — no passwords or authentication required.

Each device sends CDP advertisements out of its interfaces, and neighbors use these messages to gather details such as:

* **Device Identifier:** Typically the hostname.
* **Address List:** Includes IP and MAC addresses.
* **Port Identifier:** The remote interface that sent the CDP message.
* **Capabilities List:** Device roles (e.g., router, switch).
* **Platform:** Model and OS version.

**CDP Commands:**

| Command                            | Description                                                          |
| ---------------------------------- | -------------------------------------------------------------------- |
| `show cdp neighbors [type number]` | Displays summary info about each neighbor (or a specific interface). |
| `show cdp neighbors detail`        | Provides detailed information about all neighbors.                   |
| `show cdp entry <name>`            | Displays details about a specific neighbor.                          |

CDP packets are encapsulated in **Layer 2 frames** using multicast MAC address `0100.0CCC.CCCC`. These messages are **not forwarded** beyond directly connected devices.

---

### Configuring and Verifying CDP

CDP is **enabled by default** globally and on all interfaces.

* Disable CDP on an interface:

  ```
  no cdp enable
  ```
* Re-enable CDP:

  ```
  cdp enable
  ```
* Disable or enable globally:

  ```
  no cdp run
  cdp run
  ```

**Verification Commands:**

| Command                            | Description                                             |
| ---------------------------------- | ------------------------------------------------------- |
| `show cdp`                         | Shows global CDP status and timers.                     |
| `show cdp interface [type number]` | Shows interface-level CDP status.                       |
| `show cdp traffic`                 | Displays CDP statistics for sent and received messages. |

**Default timers:**

* Advertisement: every 60 seconds
* Holdtime: 180 seconds

| CDP Command              | LLDP Command              | Description                                             |
| ------------------------ | ------------------------- | ------------------------------------------------------- |
| `cdp timer <seconds>`    | `lldp timer <seconds>`    | Sets message transmission interval.                     |
| `cdp holdtime <seconds>` | `lldp holdtime <seconds>` | Sets how long neighbor info is retained.                |
| N/A                      | `lldp reinit <seconds>`   | Wait time before first LLDP message after interface up. |

---

### Discovering Devices with LLDP

**Link Layer Discovery Protocol (LLDP)** is an IEEE standard (802.1AB) that performs similar functions to CDP but is **vendor-neutral**.

Key differences between **CDP** and **LLDP**:

* LLDP uses **B** for switch capability (bridge).
* LLDP doesn’t list **IGMP** capability.
* LLDP omits platform details.
* LLDP lists **only enabled capabilities**, while CDP lists all supported ones.

**Useful Commands:**

| Command                      | Description                                 |
| ---------------------------- | ------------------------------------------- |
| `show lldp neighbors`        | Lists all discovered neighbors.             |
| `show lldp neighbors detail` | Provides detailed info about each neighbor. |
| `show lldp entry <hostname>` | Displays data for a specific neighbor.      |

LLDP messages use the multicast MAC address `0180.C200.000E` and are not forwarded beyond directly connected devices.

---

### Configuring and Verifying LLDP

On Cisco devices, **LLDP is disabled by default**.

| Command                              | Mode      | Description                               |
| ------------------------------------ | --------- | ----------------------------------------- |
| `lldp run` / `no lldp run`           | Global    | Enables or disables LLDP globally.        |
| `lldp transmit` / `no lldp transmit` | Interface | Enables/disables sending LLDP messages.   |
| `lldp receive` / `no lldp receive`   | Interface | Enables/disables receiving LLDP messages. |

LLDP uses timers similar to CDP:

* **Send timer:** 30 seconds
* **Hold timer:** 120 seconds

Verification uses the same syntax as CDP commands but replaces `cdp` with `lldp`.

---

### LLDP-MED and TLVs

LLDP extends its capabilities using **Type-Length-Value (TLV)** structures — a flexible format for defining additional data. Each TLV includes:

* **Type:** Identifies the kind of information.
* **Length:** Specifies the TLV’s size.
* **Value:** Contains the actual data.

**LLDP-MED (Media Endpoint Discovery)** extends LLDP with endpoint-specific TLVs — often used between switches and VoIP phones to exchange details like power requirements, VLAN IDs, and device capabilities.

LLDP-MED operates automatically once both devices recognize support for it; no additional configuration is required.
