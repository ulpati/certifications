## Installing Cisco Routers

In a typical WAN environment, serial links that connect through a service provider terminate at a **Channel Service Unit/Data Service Unit (CSU/DSU)**.  
This component may either be a **standalone device** or integrated directly into the router’s hardware.

Here’s how to properly install a Cisco router:

1. **Connect Ethernet LAN Interfaces**  
   Use a standard RJ-45 copper Ethernet cable to connect the router’s Ethernet port to a LAN switch port.

2. **Connect Serial WAN Ports**  
   - **External CSU/DSU:** Connect the router’s serial interface to the CSU/DSU, and then connect the CSU/DSU to the service provider’s line.  
   - **Internal CSU/DSU:** Connect the router’s serial interface directly to the line from the telecommunications provider.

3. **Connect Ethernet WAN Ports**  
   - Confirm the **Ethernet standard** and **SFP (Small Form-Factor Pluggable)** type required for the WAN connection.  
   - Install the appropriate SFP modules into the router, and then connect the Ethernet cable between the two WAN endpoints.

4. **Console Access**  
   Connect a console cable between the router’s console port and a PC to perform the initial configuration.

5. **Power Connection**  
   Attach the power cord from an outlet to the router’s power port.

6. **Power On**  
   Use the router’s power switch to turn it on.

Following these steps ensures that both LAN and WAN interfaces are properly connected and ready for configuration.

## Enabling IPv4 Support on Router Interfaces

For a router to actively route packets, its interfaces must be properly configured with IP addressing and operational status enabled.

### Router Interface Overview

The router’s **CLI (Command-Line Interface)** behaves similarly to that of a Cisco switch.  
However, routers require interface-specific configuration to handle Layer 3 (network layer) functions.

---

### Interface Status Codes

Each router interface shows two key status indicators:

| **Name** | **Location** | **Meaning** |
|:--|:--|:--|
| **Line Status** | First status code | Represents Layer 1 (Physical layer) — whether the cable is installed, correct, and connected to a powered device. |
| **Protocol Status** | Second status code | Represents Layer 2 (Data Link layer) — typically indicates encapsulation or protocol mismatches. It always shows *down* when Line Status is *down*. |

**Common Interface Status Combinations:**

| **Line Status** | **Protocol Status** | **Typical Reasons** |
|:--|:--|:--|
| Administratively Down | Down | The interface has been manually disabled with the `shutdown` command. |
| Down | Down | The interface is not shut down, but the physical layer is inactive — no cable, power-off device, or speed mismatch. |
| Up | Down | Layer 1 is working, but Layer 2 is not — commonly due to encapsulation mismatches (e.g., one side using PPP and the other using HDLC). |
| Up | Up | Both the physical and data-link layers are operational. |

---

### Configuring Router Interface IP Addresses

By default, router interfaces have no IP address assigned (`no ip address`) and are usually administratively down.  
To make an interface functional, it must be **enabled** and **configured** with an IP address and subnet mask.

Use the following commands:
```
interface <type> <number>
ip address <address> <mask>
no shutdown
```

These commands assign the IP address and bring the interface up.

**Useful Commands to Verify Interface Configuration**:
| **Command**                     | **IP Configuration Displayed** | **Interface Status Shown** |
| :------------------------------ | :----------------------------- | :------------------------- |
| `show ip interface brief`       | IP Address                     | Yes                        |
| `show protocols <type number>`  | IP Address and Mask            | Yes                        |
| `show interfaces <type number>` | IP Address and Mask            | Yes                        |

These verification commands provide quick visibility into interface status, addressing, and protocol state.

### Ethernet Interface Autonegotiation

Autonegotiation determines the **speed** and **duplex mode** of an Ethernet interface.
Routers follow the same general best practices as switches:
- Use autonegotiation when possible for compatibility.
- Manually configure speed and duplex if mismatches occur.

**IOS Commands**:
```
speed <number>
duplex <half/full>
```

**IOS XE Commands**:
```
no negotiation auto
speed <number>
duplex <half/full>
```

Correctly setting these parameters helps ensure optimal link performance and reduces the risk of connectivity issues caused by mismatched duplex modes.
