## 🌐 Comparing Dynamic Routing Protocol Features

Routers can add routes to their routing tables in three main ways:
1. **Connected routes** – learned automatically from active interfaces.  
2. **Static routes** – manually configured by administrators.  
3. **Dynamic routes** – learned via **routing protocols** that exchange information with other routers.

A **routing protocol** is a set of algorithms, rules, and messages that routers use to discover and share network paths.  
It determines the **best route** for each destination based on metrics and network topology.  
Common examples include **RIP**, **EIGRP**, **OSPF**, and **BGP**.  

> All references in this article refer to **OSPFv2** (for IPv4).

A **routed** (or **routable**) protocol, on the other hand, defines the format and structure of packets that can be forwarded by routers — such as **IPv4** and **IPv6**.

---

### 🧩 Core Functions of Routing Protocols

Cisco IOS supports several IP routing protocols, each performing these essential tasks:

- **Learn** routes to IP subnets from neighbors.  
- **Advertise** routes to other routers.  
- **Select** the best route when multiple paths exist, based on metrics.  
- **React** to topology changes (such as a link failure) by recalculating and redistributing routes — a process known as **convergence**.

A protocol’s **convergence speed** and **loop-prevention** capabilities are key factors when choosing which routing protocol to use.

---

### 🏛️ Interior vs. Exterior Routing Protocols

- **Interior Gateway Protocols (IGPs):** Used *within* a single organization’s network (autonomous system).  
- **Exterior Gateway Protocols (EGPs):** Used *between* different autonomous systems (for example, between ISPs).  

An **Autonomous System (AS)** represents a network or group of networks managed under a single administrative domain.  

Today, **BGP (Border Gateway Protocol)** is the only EGP in wide use.

---

### ⚙️ Comparing IGP Algorithms

Each routing protocol uses a unique algorithm to learn and calculate routes.  
Three major algorithm categories are:

| Type | Description |
|------|--------------|
| **Distance Vector** | Determines routes based on distance (hop count) and direction (vector). |
| **Advanced Distance Vector** | Uses metrics like bandwidth and delay for more accurate decisions (e.g., EIGRP). |
| **Link-State** | Builds a complete map of the network and computes the shortest path (e.g., OSPF). |

---

### 📊 Routing Metrics

Metrics help routers choose the **best route** among multiple options. The lower the metric, the better the route.

| Protocol | Metric | Description |
|-----------|---------|-------------|
| **RIPv2** | Hop Count | Number of routers (hops) between the source and destination. |
| **OSPF** | Cost | Sum of all interface costs in the path (based on interface bandwidth). |
| **EIGRP** | Composite Metric | Combines bandwidth and delay to determine the best route. |

> The `bandwidth` interface command does **not** affect actual speed — it only informs the router about the assumed interface bandwidth for metric calculations.

## 🧠 OSPF Concepts and Operation

### Overview

OSPF (Open Shortest Path First) is a **link-state routing protocol** that builds a complete view of the network by exchanging information about routers, interfaces, and link statuses.  

Once every router shares this data through **flooding**, each one uses it to calculate optimal routes independently.

---

### 🗺️ Topology Information and LSAs

OSPF organizes network topology data using:
- **Link-State Advertisements (LSAs):** Packets that describe parts of the network (interfaces, routers, links, etc.).  
- **Link-State Database (LSDB):** A collection of all LSAs known by a router.

Routers flood LSAs throughout the area to ensure all devices maintain the same LSDB. To prevent endless loops, routers exchange summaries first, asking neighbors whether they already have a specific LSA before sending it.

Each LSA is **re-flooded every 30 minutes** or when a topology change occurs.

---

### 🧮 Dijkstra’s Shortest Path First (SPF) Algorithm

Once routers share LSAs, they each apply **Dijkstra’s SPF algorithm** to compute the shortest paths.  
This process determines which routes to install in the **IP routing table**, including:
- The destination subnet and mask.  
- The next-hop IP address.  
- The outgoing interface.

#### OSPF Operation Stages:
1. **Becoming neighbors:** Routers discover each other and form relationships.  
2. **Exchanging databases:** Routers share LSAs to synchronize LSDBs.  
3. **Calculating best routes:** Each router independently runs SPF and updates its routing table.

## 🤝 Becoming OSPF Neighbors

### Neighbor Formation

Two routers become **OSPF neighbors** when:
- They are both configured for OSPF.  
- They share the same subnet.  
- Their OSPF parameters (like area ID, timers, authentication, and network type) are compatible.

Routers use **OSPF Hello packets** to introduce themselves and verify these parameters.  

Check OSPF neighbors with:
```
show ip ospf neighbor
```

To display the OSPF database: `show ip ospf database`

---

### Exchanging Hello Packets and Router IDs

Each router advertises a **Router ID (RID)** — a unique 32-bit identifier, often chosen automatically from the highest IP address on an active interface (or set manually).

Routers send Hello packets to multicast address **224.0.0.5** and listen for the same to discover neighbors.

**Example of the 2-Way State Between Two Routers:**

1. **R1 → R2:** Sends Hello, RID 1.1.1.1.
2. **R2 → R1:** Responds with Hello, lists R1’s RID (Init → 2-Way).
3. **R1 → R2:** Confirms 2-Way state.

Once both routers reach the **2-Way** state, they can proceed to database exchange.

---

### Exchanging LSDBs Between Neighbors

#### Database Synchronization

Routers exchange LSAs in a structured process:
1. **Database Description (DD):** Summarizes available LSAs.
2. **Link-State Request (LSR):** Requests any missing LSAs.
3. **Link-State Update (LSU):** Sends requested LSAs.
4. **Acknowledgment:** Confirms successful exchange.

At the end of this process, both routers reach the **Full** adjacency state.

---

#### Maintaining Neighbor Relationships

Routers maintain OSPF neighbor states using two timers:
- **Hello Interval:** How often Hello packets are sent.
- **Dead Interval:** How long to wait before declaring a neighbor down (default = 4 × Hello interval).

If no Hellos are received within the Dead Interval, the router assumes the neighbor is unavailable and updates the LSDB.

Additionally:
- Changed LSAs are immediately flooded.
- All LSAs are reflooded every **30 minutes**, even if unchanged.

---

### Designated Routers (DR) and Backup DRs (BDR)

On broadcast networks (like Ethernet), OSPF elects:
- One **Designated Router (DR)**
- One **Backup Designated Router (BDR)**

The DR coordinates LSDB exchanges and sends updates using multicast **224.0.0.5**, while routers reply to **224.0.0.6** (used by the DR/BDR).

Only the DR and BDR reach a **Full** state with all routers; other routers (called **DROthers**) form partial adjacencies to reduce overhead.

---

### Calculating Best Routes with SPF

OSPF calculates the **shortest path** to each subnet based on **cumulative interface costs** — the sum of all OSPF costs along the route.

A **lower total cost** means a better path, which is then installed in the routing table.

## OSPF Areas and LSAs

### Understanding OSPF Areas

Areas are a key scalability feature in OSPF.
They divide large networks into smaller sections to reduce SPF processing time and limit the size of the LSDB.

Guidelines:
- All interfaces in the same subnet must belong to the same area.
- Each area must be contiguous.
- **Area Border Routers (ABRs)** connect multiple areas (including Area 0, the backbone).
- All non-backbone areas must connect to the **backbone (Area 0)** directly or through an ABR.

| Term                         | Description                                                    |
| ---------------------------- | -------------------------------------------------------------- |
| **Area Border Router (ABR)** | Connects the backbone (Area 0) with at least one other area.   |
| **Backbone Router**          | Any router in Area 0 (includes ABRs).                          |
| **Internal Router**          | A router with all interfaces in the same area (non-backbone).  |
| **Area**                     | A logical grouping of routers and links sharing the same LSDB. |
| **Backbone Area**            | Central OSPF area (Area 0).                                    |
| **Intra-area Route**         | Route to a subnet within the same area.                        |
| **Interarea Route**          | Route to a subnet located in another area.                     |

---

### Benefits of Using Areas

- Smaller LSDBs reduce CPU and memory usage.
- Faster convergence after topology changes.
- Less routing information to advertise between areas.
- Improved scalability and efficiency in large networks.

### Common OSPFv2 LSA Types

| LSA Name             | Type | Purpose                           | Information Contained          |
| -------------------- | ---- | --------------------------------- | ------------------------------ |
| **Router (Type 1)**  | 1    | Describes a router’s interfaces   | RID, IP addresses, link states |
| **Network (Type 2)** | 2    | Describes a network with a DR/BDR | DR/BDR IPs, subnet ID, mask    |
| **Summary (Type 3)** | 3    | Describes networks in other areas | Subnet ID, mask, ABR RID       |
