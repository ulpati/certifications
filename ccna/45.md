## Understanding First Hop Redundancy Protocols

**First Hop Redundancy Protocols (FHRP)** are a group of technologies designed to ensure that end devices can continue communicating with the network gateway even if one router fails. They provide redundancy for the *first hop* — the default gateway through which traffic exits a local subnet.

---

## Why Networks Need Redundancy

Modern networks rely on redundancy to maintain high availability. A **single point of failure**—such as one router or link—can bring down part or all of a network.  
To avoid this, network engineers identify potential failure points and introduce **backup paths or devices**. By adding redundant routers and links, they ensure the network remains operational even if one component goes offline.

---

## The Purpose of First Hop Redundancy

Without FHRP, hosts would need to manually change their default gateway settings if a router failed. FHRPs automate this process by making multiple routers appear as **a single virtual gateway**.

Key features of an FHRP include:

- Hosts use a single, unchanging **virtual IP address (VIP)** as their default gateway.  
- Routers participating in the FHRP share the same VIP and coordinate through protocol messages.  
- If the active router fails, another router automatically takes over without user intervention.  
- The transition happens seamlessly, maintaining uninterrupted communication for end users.

## Hot Standby Router Protocol (HSRP)

**HSRP** is a Cisco-proprietary protocol that allows multiple routers to cooperate in providing gateway redundancy. At any moment, one router is **active**, handling traffic, while the other(s) remain **standby**, ready to take over if needed.

### Virtual IP and MAC Addresses

HSRP uses a **virtual IP (VIP)** and a corresponding **virtual MAC (VMAC)** address shared among participating routers.  
Only the *active router* uses these addresses at a time. The others listen and wait to take over if the active router becomes unavailable.

The election process works as follows:
- The router with the **highest HSRP priority** becomes active.  
- If priorities tie, the router with the **highest IP address** wins.  
- Additional routers beyond the active and standby states remain in a *listen* state, awaiting a change.

Hosts set their default gateway to the VIP rather than any router’s physical IP address.

---

### HSRP Failover Process

HSRP routers exchange **Hello messages** at regular intervals.  
If the standby router doesn’t receive a Hello within the **Hold time** (typically three times the Hello interval), it assumes the active router is down and takes over.

To redirect traffic correctly:
- The new active router begins using the shared VIP and VMAC.  
- LAN switches update their MAC address tables after receiving a **gratuitous ARP** from the new active router.  
- This ensures all devices forward frames to the correct router.

---

### Load Balancing with HSRP

Although HSRP itself doesn’t support load balancing within a single subnet, it can be configured across **multiple VLANs or groups**.  
By assigning different routers as active in different subnets, administrators can distribute the overall traffic load evenly.

---

### Interface Tracking and Preemption

HSRP can **track interface states or routes**.  
If a tracked interface fails, the router’s priority decreases, allowing another router to take over.

**Preemption** allows a higher-priority router to reclaim the active role once it recovers.  
By default, preemption is disabled but can be enabled for faster recovery.

## VRRP and GLBP: Alternative Redundancy Options

### Virtual Router Redundancy Protocol (VRRP)

**VRRP**, defined in RFC 5798, provides redundancy similar to HSRP but is an **open standard**.  
It supports preemption and load balancing through multiple VRRP groups.  
The key difference lies in its default parameters, configuration style, and addressing conventions.

---

### Gateway Load Balancing Protocol (GLBP)

**GLBP**, a Cisco innovation, extends redundancy by enabling **active/active load balancing**.  
Instead of one virtual MAC for the entire group, each participating router gets its **own virtual MAC**.  
This allows all routers to forward traffic simultaneously, distributing the load across multiple devices.

| Protocol | Cisco Proprietary | IPv6 Support | Load Balancing | Multicast Address | Group Range |
|-----------|------------------|---------------|----------------|-------------------|--------------|
| HSRPv2 | Yes | Yes | No | 224.0.0.102 | 0–4095 |
| VRRPv3 | No | Yes | No | 224.0.0.18 | 1–255 |
| GLBP | Yes | Yes | Yes | 224.0.0.102 | 0–1023 |

---

### GLBP Operation

GLBP defines two primary roles:

- **Active Virtual Gateway (AVG):**  
  Handles all ARP replies for the shared VIP and assigns virtual MACs to participating routers.

- **Active Virtual Forwarder (AVF):**  
  Each router serves as an AVF, forwarding packets destined to its assigned virtual MAC address.

When the AVG fails, another router in the group automatically takes over as the new AVG.  
If an AVF fails, the AVG reassigns its virtual MAC to a functional router to maintain uninterrupted service.

This dynamic process ensures both **high availability** and **efficient load balancing** across routers.

---

## Summary

FHRPs such as HSRP, VRRP, and GLBP form the backbone of **gateway redundancy** in enterprise networks.  
They ensure continuous network operation during router failures and improve traffic distribution efficiency.  
While HSRP and VRRP follow an *active/standby* model, GLBP takes it further by enabling true *active/active load balancing*.
