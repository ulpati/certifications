## 🏙️ Metro Ethernet (MetroE)

**Metro Ethernet** represents a family of WAN services that share two key characteristics:  
1. The customer connects to the service provider using **Ethernet physical links**.  
2. The provider delivers a **Layer 2 service**, forwarding Ethernet frames between customer sites much like a large, distributed LAN switch.

---

## 🧩 Metro Ethernet Physical Design and Topology

To use a MetroE service, every enterprise location must connect to the provider with at least one Ethernet link. Internal routers at different sites do not connect directly to one another—the service provider builds its own MetroE transport network.

Service providers place Ethernet switching devices close to customer sites in facilities known as **points of presence (PoPs)**. Their goal is to position equipment within the physical limits of Ethernet fiber standards.

The link connecting the customer to the provider is called an **access link**, and the boundary between the two networks is the **user network interface (UNI)**. Everything beyond the UNI is hidden from the customer; the service provider simply guarantees Ethernet frame transport across the WAN. The UNI supports standard IEEE Ethernet technologies.

---

## 🌐 Ethernet WAN Services and Topologies

The **Metro Ethernet Forum (MEF)** defines several types of MetroE services, each with a distinct topology:

| MEF Service | Short Name | Topology | Description |
|-------------|------------|-----------|-------------|
| Ethernet Line | **E-Line** | Point-to-point | Connects exactly two customer devices, similar to a leased line. |
| Ethernet LAN | **E-LAN** | Full mesh | All sites can exchange frames directly with one another. |
| Ethernet Tree | **E-Tree** | Hub-and-spoke / Partial mesh | A central “hub” site communicates with multiple remote sites, but the remote sites do not communicate directly. |

You may also encounter terms such as **VPWS**, **VPLS**, or **EoMPLS**. These refer to implementations where the provider uses MPLS internally but presents the service to customers as Ethernet.

---

### 🔗 E-Line Service (Point-to-Point)

An **E-Line** connects two sites using an access link at each end. This service is built around an **Ethernet Virtual Connection (EVC)**, which defines which customer devices may exchange frames. A point-to-point EVC guarantees that only the two endpoints communicate.

### 🖧 E-LAN Service (Full Mesh)

An **E-LAN** service allows all connected devices to communicate directly, creating a full-mesh Layer 2 environment. Functionally, it behaves like a distributed Ethernet switch spanning multiple sites.

---

## 🧭 Layer 3 Design with Metro Ethernet

### L3 Design with E-Line
A point-to-point E-Line behaves like a single Layer 3 link:
- One IP subnet per E-Line  
- Routing adjacency forms only over that specific link  

### L3 Design with E-LAN  
Routers attached to an E-LAN effectively operate on the same IP subnet, allowing all of them to become neighbors using standard routing protocols.

## 🚀 Multiprotocol Label Switching (MPLS)

**MPLS** provides a WAN service that routes IP packets between customer sites. Each enterprise site connects to the service provider using an access link, and the provider’s MPLS network carries packets across a large geographic region.

MPLS overcomes the limitations of a traditional provider-wide IP network by using **label switching** and **MPLS VPNs**, allowing multiple customers to share the same infrastructure while keeping their traffic isolated.

Provider routers at the MPLS edge add and remove an MPLS header. Devices inside the MPLS core forward packets based on the **label field**, ensuring traffic separation and controlled forwarding paths.

Although MPLS VPNs offer Layer 3 services, MPLS is often called a **Layer 2.5** technology because its header sits between Layer 2 and Layer 3.

### Key SP Functions in MPLS VPNs
- Form routing adjacencies with customer routers  
- Learn customer routes  
- Advertise those routes to other customer sites  
- Decide which labels to insert or remove for forwarding  

A critical point: MPLS VPNs **segregate traffic** but **do not encrypt** it.

---

## 🏗️ MPLS VPN Physical Design

Two key terms apply:
- **CE (Customer Edge):** Router located at the customer site  
- **PE (Provider Edge):** Router at the service provider site, terminating the access link  

Various data-link technologies can be used on MPLS access links.

---

## 🧭 Layer 3 Behavior with MPLS VPN

Customer routers (CE) exchange routes only with the provider edge (PE), not with each other.  
PE routers share customer routes using **Multiprotocol BGP (MP-BGP)** combined with **VRF instances**, ensuring routes from different customers remain isolated.

# 🌍 Internet VPNs

Businesses can use the public Internet as a WAN service by connecting each site to an ISP and establishing an **Internet VPN**. Encryption ensures privacy even though packets travel through a public network.

---

## 🌐 Internet Access Technologies

### 🟦 Digital Subscriber Line (DSL)

DSL evolved from older analog modem and ISDN services. It uses frequencies outside the voice band to transmit digital data while allowing simultaneous phone calls.

At the telecom office, a **DSLAM** separates data and voice traffic:
- Digital data → routed toward the Internet  
- Voice → sent to the voice switch  

### 🟥 Cable Internet

Cable Internet uses coaxial CATV cabling and supports asymmetric speeds (faster download than upload). Data and TV signals share the same infrastructure but are separated by the provider using dedicated routing and video equipment.

### 🟩 Wireless WAN (4G, 5G)

Mobile devices communicate with nearby cellular towers via radio signals. The provider’s infrastructure routes traffic through its IP network and onward to the Internet. Routers with cellular interfaces can also use these networks for WAN connectivity.

### 🟨 Fiber (Ethernet) Internet

Some ISPs offer fiber-based Internet services delivered using Ethernet protocols over fiber-optic cabling, providing high speeds and low latency.

---

# 🔐 Internet VPN Fundamentals

VPNs aim to replicate the security of a private WAN using the public Internet. Core features include:

- **Confidentiality:** encrypted data  
- **Authentication:** verifying the sender  
- **Integrity:** ensuring packets are not modified  
- **Anti-replay:** preventing attackers from resending captured packets  

VPN devices create a **VPN tunnel**, adding headers and encrypting the original IP packet.

---

## 🏢 Site-to-Site VPNs with IPsec

A **site-to-site VPN** maintains a constant tunnel between two locations. All local devices benefit transparently.

**IPsec** provides the encryption and security mechanisms. It uses pairs of algorithms (encrypt/decrypt) and a **shared session key**.

General IPsec process:
1. Sender encrypts data using the session key  
2. Sender encapsulates encrypted data with new headers  
3. Packet crosses the Internet  
4. Receiver decrypts using the same session key  

---

## 👤 Remote Access VPNs with IPsec

Remote users can initiate their own VPN sessions. This requires:
- VPN client software on the user device  
- A VPN concentrator configured by the enterprise  

Remote access typically uses **IPsec transport mode**, which encrypts only the payload, not the IP header.

### Comparison: Site-to-Site vs Remote Access IPsec

| Attribute | Site-to-Site | Remote Access |
|----------|--------------|----------------|
| VPN client needed? | No | Yes |
| Devices supported | Many | One |
| Typical use | Always-on | On-demand |
| IPsec tunnel mode | Yes | No |
| IPsec transport mode | No | Yes |

---

## 🔒 Remote Access VPNs with TLS

Most modern web traffic uses HTTPS, which relies on **TLS**. TLS encrypts application-layer data and authenticates endpoints.

TLS can also be used for remote access VPNs, providing secure connectivity without requiring IPsec.
