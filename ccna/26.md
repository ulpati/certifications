## Global Unicast Addressing Concepts  

### Public and Private IPv6 Addresses  

**Global Unicast Addresses (GUAs)** are the IPv6 equivalent of **public IPv4 addresses**. When an organization requires IPv6 connectivity, it requests a registered IPv6 address block from a regional Internet registry (such as ARIN or RIPE). This block is assigned as the **global routing prefix**, and only that organization can use addresses within this range. Every IPv6 address beginning with that prefix becomes part of the company’s global unicast space.  

**Unique Local Addresses (ULAs)**, on the other hand, behave similarly to **private IPv4 addresses** (like 10.0.0.0/8 or 192.168.0.0/16). Multiple organizations can use the same ULA ranges without conflict, as they are not globally routable and do not require registration with an external authority.  

---

### Address Ranges for Global Unicast Addresses  

IPv6 addresses beginning with hexadecimal values **2** or **3** are reserved for **Global Unicast** use. This range is defined by the prefix **2000::/3**.  

| **Address Type** | **First Hex Digits** |
|------------------|----------------------|
| Global Unicast   | 2 or 3               |
| Unique Local     | FD                   |
| Multicast        | FF                   |
| Link Local       | FE80                 |

## IPv6 Subnetting Using Global Unicast Addresses  

### The Mechanism of Subnetting IPv6 Global Unicast Addresses  

In IPv6, the **global routing prefix** represents the organization’s allocated network portion, functioning much like the **network ID** in IPv4. The **subnet ID** is comparable to the subnet field in IPv4, while the **interface ID** represents the host portion of the address.  

Once an organization receives a global routing prefix, its length (often `/48`) typically remains fixed. According to multiple RFCs, the **interface ID** should be **64 bits long** to support dynamic addressing mechanisms such as **Stateless Address Autoconfiguration (SLAAC)**.  

Given a 64-bit interface ID, the **subnet ID** field usually consists of the remaining bits between the prefix length and 64.  

---

### Listing the IPv6 Subnet Prefix (Subnet ID)  

- **Subnet Prefix:** The formal term describing the combination of the global routing prefix and the subnet ID.  
- **Subnet ID or Prefix ID:** Informal terms that refer to the same concept.  

To determine the subnet prefix from an IPv6 address and prefix length, the process is identical for both **Global Unicast** and **Unique Local** addresses.  

---

### Listing All IPv6 Subnets  

To identify every possible subnet within a global routing prefix:  

1. Start with the **global routing prefix**.  
2. Assign a **different value** in the subnet field for each subnet.  
3. Set all bits in the **interface ID** portion to **zero**.  

Each **subnet prefix** (also known as the **subnet router anycast address**) is reserved and should not be used as a regular host address.  

---

### Assigning Addresses to Hosts in a Subnet  

IPv6 allows interfaces to obtain addresses either **statically** or **dynamically**:  

- **Static Configuration:** The network administrator manually assigns the address, prefix length, default gateway, and DNS information.  
- **Dynamic Configuration:** Devices can automatically acquire configuration data through **DHCPv6** or **SLAAC (Stateless Address Autoconfiguration)**.  

This flexibility simplifies deployment and supports both large enterprise networks and smaller internal systems.

## Unique Local Unicast Addresses (ULAs)  

**Unique Local Addresses (ULAs)** serve as **private IPv6 addresses** that are not intended for Internet routing. They allow internal communication within an organization without depending on global address space allocation.  

When creating ULA addresses, network engineers should follow these conventions:  

- Begin with **FD** as the first two hexadecimal digits.  
- Generate a **40-bit Global ID**, ideally random and unique.  
- Combine the prefix `FD` and the Global ID to form a **48-bit prefix**.  
- Use the next **16 bits** as the subnet field.  
- Reserve the remaining **64 bits** for the interface ID.  

This structure allows for a consistent `/64` prefix length across internal subnets while maintaining a globally unique local address space.  

---

### Subnetting with Unique Local IPv6 Addresses  

Subnetting **ULAs** follows the same logic as subnetting **GUAs**, except that ULAs are self-generated rather than assigned by IANA.  

To create a ULA prefix:  
1. Start with **FD**.  
2. Generate ten random hexadecimal digits to form the 40-bit **Global ID**.  
3. Combine them into a 48-bit prefix (for example, `FD12:3456:789A::/48`).  
4. Use the **fourth quartet** to represent your subnet ID field.  

Each subnet then maintains a 64-bit interface ID section, consistent with IPv6 standards.  

---

### The Need for Globally Unique Local Addresses  

**RFC 4193** emphasizes the importance of ensuring that your locally generated addresses remain **statistically unique** across different organizations. This prevents address collisions if two networks are later merged or connected through a VPN.  

The RFC also outlines a **recommended randomization process** for generating the 40-bit Global ID. By following this guidance, companies can create ULAs that are effectively unique worldwide, even without central registration.
