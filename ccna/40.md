## Understanding Port Security in Cisco Switches  

Port security is a feature that helps protect switch interfaces from unauthorized access. It does so by monitoring incoming Ethernet frames and ensuring that only trusted devices are allowed to communicate through a given port.

Here’s a summary of how port security operates across all configurations:

- It analyzes incoming frames on a switch port to detect potential violations.  
- It defines the maximum number of unique source MAC addresses that can be associated with a port.  
- It maintains a list and a counter of learned MAC addresses for that port.  
- If a new, unauthorized MAC address exceeds the defined limit, the switch treats it as a violation.  
- When a violation occurs, the switch discards traffic from that MAC address and may take additional actions depending on the configured violation mode.  

In practice, you can configure port security in several flexible ways:  

- Specify up to three predefined MAC addresses for a single port.  
- Allow the first three learned MAC addresses to be dynamically secured.  
- Predefine one MAC address while dynamically learning the remaining two.  

To simplify configuration, Cisco introduced **sticky secure MAC addresses**, a feature that automatically learns and stores MAC addresses in the running configuration. This eliminates the need to manually determine and enter MAC addresses for each connected device.

## Configuring Port Security  

Port security can be applied to both **access** and **trunk** interfaces. However, the interface must be statically configured for one of these modes.  

Follow these steps to set up port security on a switch interface:  

1. Configure the port as static access or trunk:  
   ```
   switchport mode access
   ```

or

```
switchport mode trunk
```

2. Enable port security:

   ```
   switchport port-security
   ```
3. *(Optional)* Set the maximum number of allowed MAC addresses (default is 1):

   ```
   switchport port-security maximum <number>
   ```
4. *(Optional)* Choose the violation mode:

   ```
   switchport port-security violation {protect | restrict | shutdown}
   ```
5. *(Optional)* Define specific allowed MAC addresses:

   ```
   switchport port-security mac-address <mac-address>
   ```
6. *(Optional)* Enable sticky learning for dynamic MAC addresses:

   ```
   switchport port-security mac-address sticky
   ```

> **Tip:** Sticky MAC addresses are saved only in the running configuration. Use `copy running-config startup-config` to make them persistent after reboot.

**Special cases:**

* On **voice ports**, set the maximum MAC addresses to at least two — one for the IP phone and one for a connected PC.
* For **EtherChannel** interfaces, configure port security on the logical *port-channel* interface, not on the individual member ports.

## Verifying Port Security

Use the following command to check the configuration and current state of port security on a specific interface:

```
show port-security interface <interface-id>
```

This command displays:

* Current port security settings
* The number of secure MAC addresses
* Any existing security violations

To view which MAC addresses are secured:

```
show mac address-table secure
```

For static and secure entries:

```
show mac address-table static
```

## Port Security Violation Modes

Violation modes determine how the switch responds when an unauthorized device attempts to use a secured port.

| **Violation Mode** | **Discards Traffic** | **Logs / SNMP Alerts** | **Disables Port (Err-Disabled)** |
| ------------------ | -------------------- | ---------------------- | -------------------------------- |
| **Protect**        | ✅ Yes                | ❌ No                   | ❌ No                             |
| **Restrict**       | ✅ Yes                | ✅ Yes                  | ❌ No                             |
| **Shutdown**       | ✅ Yes                | ✅ Yes                  | ✅ Yes                            |

---

### Shutdown Mode

When a violation occurs in **shutdown** mode:

* The port is placed in the **err-disabled** state (`show interfaces` or `show interfaces status`).
* The port’s security state becomes **secure-shutdown** (`show port-security`).
* The interface stops all frame transmission and reception.

To manually recover:

```
shutdown
no shutdown
```

Or, configure automatic recovery with:

```
errdisable recovery cause psecure-violation
errdisable recovery interval <seconds>
```

---

### Protect and Restrict Modes

* **Protect Mode:**
  Simply drops unauthorized frames. No log messages or counters are updated, and the interface remains active.

* **Restrict Mode:**
  Offers a middle ground — it drops unauthorized traffic **and** logs the event, increments violation counters, and can trigger SNMP notifications.

---

## Key Takeaways

* Port security is an essential defense against unauthorized device access.
* Use sticky MAC learning to automate secure address configuration.
* Choose an appropriate violation mode based on your security policy — **Protect**, **Restrict**, or **Shutdown**.
* Always save your configuration to retain learned MAC addresses across reboots.
