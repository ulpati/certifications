## VLAN Routing with Router 802.1Q Trunks

There are several ways to route traffic between VLANs in a LAN:

- **Router with one interface per VLAN** (rarely used today).  
- **Router-on-a-stick (ROAS)** — a router connects to a switch via a single trunk port.  
- **Layer 3 switch using Switched Virtual Interfaces (SVIs)**.  
- **Layer 3 switch using routed ports or Layer 3 EtherChannels**.  
- **Router with integrated switch ports**, configured similarly to a Layer 3 switch.

---

### Configuring Router-on-a-Stick (ROAS)

ROAS enables a router to route traffic between VLANs using **802.1Q trunking**. The router uses a single physical interface, divided into **subinterfaces**, each representing a different VLAN. Each subinterface is assigned an IP address within its corresponding VLAN subnet.

#### Configuration Steps

1. **Create subinterfaces:** `interface <type/number.subint>`
    
    Each VLAN to be routed requires a unique subinterface.

2. **Enable 802.1Q encapsulation:** `encapsulation dot1q <vlan_id>`

    Associates the subinterface with a specific VLAN.

3. **Assign an IP address:** `ip address <ip_address> <mask>`

Best Practice: Use the same subinterface number as the VLAN ID for consistency.

#### Configuring the Native VLAN

You can define the native VLAN in two ways:

Assign the IP address directly to the **physical interface** (no encapsulation).

Create a subinterface with: `encapsulation dot1q <vlan_id> native`

---

### Verifying ROAS

Useful commands include:
```
show ip route connected
show vlans
show interfaces trunk
show interfaces <int_type/number>
```

---

### Troubleshooting ROAS

ROAS misconfigurations can occur when VLANs are mismatched between the router and the switch. Follow these checks:
1. Ensure each VLAN has a proper `encapsulation dot1q vlan-id` command.
2. Confirm VLANs exist and are allowed on the switch trunk: `show interfaces trunk`
3. Verify each router subinterface has an IP address.
4. Check that the native VLAN matches on both router and switch.
5. Confirm that all interfaces are active (no shutdown).

## VLAN Routing with Layer 3 Switch SVIs

While ROAS is ideal for small networks, **Layer 3 switches** are preferred in larger environments.
A Layer 3 switch performs both **Layer 2 switching** and **Layer 3 routing** within the same device.

---

### Configuring Routing Using SVIs

Each VLAN is represented by a **Switched Virtual Interface (SVI)**, which acts as the default gateway for that VLAN.

**Step 1: Enable IP Routing**
- Enable hardware resources for routing (varies by switch model).
- Enter: `ip routing`

**Step 2: Configure VLAN Interfaces**
For each VLAN:
```
interface vlan <vlan_id>
ip address <ip_address> <mask>
no shutdown
```
This configuration activates IPv4 routing for that VLAN.

---

### Verifying Routing with SVIs

Check routing and VLAN status with:
```
show ip route connected
show vlans
show interfaces vlan <vlan_id>
```

---

### Troubleshooting SVIs

SVIs can operate in **autostate** (default) or **no autostate** mode.

#### SVI State with Autostate Enabled

An SVI appears up/up only if:
- The VLAN exists on the switch (locally or via VTP).
- At least one interface in the VLAN is up/up.
- The VLAN is not blocked by STP or pruned by VTP.
- Both the VLAN and SVI are administratively enabled.

#### SVI State with Autostate Disabled

When **autostate** is disabled, the VLAN interface depends solely on whether the VLAN exists.
If not, the SVI appears *up/down*.

## VLAN Routing with Layer 3 Switch Routed Ports

Layer 3 switches can also treat **physical ports** as router interfaces rather than switch ports. These are called **routed ports**.

### Implementing Routed Interfaces

Use routed ports for **point-to-point connections** between devices.

To convert a switch port into a routed port:
```
interface <int_type/number>
no switchport
ip address <ip_address> <mask>
```

---

## Layer 3 EtherChannels

A **Layer 3 EtherChannel** aggregates multiple physical links into one logical interface for routing.
This simplifies configurations and enables load balancing between switches.

### Configuration Steps

1. Configure Physical Interfaces
```
interface range <interfaces>
no switchport
channel-group <number> mode on
```
2. Configure the PortChannel Interface
```
interface port-channel <number>
no switchport
ip address <ip_address> <mask>
```

---

### Troubleshooting Layer 3 EtherChannels

Common verification and troubleshooting commands include:
```
show etherchannel summary
show interfaces port-channel <number>
show ip route connected
show interfaces status
```

**Requirements**
- All interfaces must have no switchport.
- Interfaces must use the same speed and duplex settings.
- Configuration must be identical on both sides of the EtherChannel.

---

## VLAN Routing in Routers with Integrated Switch Ports

Some routers have built-in switch ports, allowing both switching and routing in one device.

**Configuration Steps**
1. Create VLANs and Assign Access Ports
```
vlan <vlan_id>
interface <int_type/number>
switchport access vlan <vlan_id>
no shutdown
```
2. Create VLAN Interfaces (SVIs)
```
interface vlan <vlan_id>
ip address <ip_address> <mask>
no shutdown
```
3. Configure Routed Interfaces
```
interface <int_type/number>
ip address <ip_address> <mask>
```
Configure routing protocols as needed.

---

### Verifying Routing on Embedded Switch Ports

Useful commands:
```
show ip route connected
show mac address-table dynamic
show vlan-switch brief
show interfaces status
```

⚠️ Routed and switched ports use different command sets — a routed port won’t accept Layer 2 commands and vice versa.
