## Choosing the Right Subnet Mask

To select an appropriate subnet mask, follow these logical steps:

1. **Determine the number of network bits (N)** based on the address class (A, B, or C).  
2. **Find the minimum number of subnet bits (S)** such that `2^S ≥` the required number of subnets.  
3. **Find the minimum number of host bits (H)** such that `2^H - 2 ≥` the required number of hosts per subnet.  
4. If **N + S + H > 32**, no mask can satisfy the requirements.  
5. If **N + S + H = 32**, a single mask perfectly fits the need. The subnet mask can be expressed as `/P`, where `P = N + S`.  
6. If **N + S + H < 32**, more than one subnet mask could work:
   - To **maximize the number of hosts per subnet**, use the smallest possible value of S (i.e., fewer subnet bits).  
   - To **maximize the number of subnets**, use the smallest possible value of H (i.e., fewer host bits).  
   - The valid range of subnet masks lies between these two prefix lengths.

This step-by-step logic ensures flexibility in network planning while maintaining efficient address allocation.

## Finding All Subnet IDs

Given a single **Class A**, **B**, or **C** network and a subnet mask applied consistently across all subnets, we can calculate **every subnet ID** that exists within that network.

---

### The First Subnet: The Zero Subnet

The first subnet ID corresponds to the **network ID** itself.  

Cisco IOS allows or disallows the use of the zero subnet using the following commands:

- **`ip subnet-zero`** — Enables configuration of addresses in the zero subnet.  
- **`no ip subnet-zero`** — Prevents configuration within the zero subnet. This restriction affects only local router configuration commands such as `ip address` and `ip route`, but does *not* impact routes learned dynamically via routing protocols.

## Using the Magic Number Method

The **magic number** method is a practical way to identify subnet patterns.  
It is based on the difference between 256 and the subnet mask’s *interesting octet* (the one that isn’t 255 or 0).

| Octet | 1 | 2 | 3 | 4 |
|:--|:--|:--|:--|:--|
| **Mask** |   |   |   |   |
| **Magic Number** |   |   |   |   |
| **Network Number / Zero Subnet** |   |   |   |   |
| **Next Subnet** |   |   |   |   |
| **Next Subnet** |   |   |   |   |
| **Broadcast Subnet** |   |   |   |   |
| **Out of Range (Used by Process)** |   |   |   |   |

---

### Step-by-Step Process (for Fewer Than 8 Subnet Bits)

1. Write the **subnet mask** in decimal form in the first row of the chart.  
2. Identify the **interesting octet** — the octet that contains the subnet bits (not 255 or 0).  
3. Calculate the **magic number**: `256 - value of the interesting octet`.  
4. Write the **classful network number** (the same as the zero subnet) in the next row.  
5. For each new subnet:
   - Copy the uninteresting octets (those that are 255 or 0) from the previous subnet.  
   - Add the magic number to the interesting octet of the previous subnet.  
6. Stop when adding the magic number results in a value of **256**. That value is out of range, and the **previous subnet** represents the broadcast subnet.

---

### Subnets with Exactly 8 Subnet Bits

There are only two cases where exactly 8 subnet bits are used:

- A **Class A** network with a **255.255.0.0** mask.  
- A **Class B** network with a **255.255.255.0** mask.  

In these situations:
- The entire octet is used for subnet bits.  
- The **interesting octet** is the one that changes per subnet.  
- The **magic number** is `256 - 255 = 1`, meaning each subsequent subnet increases by **1** in that octet.

---

### Subnets with 9–16 Subnet Bits

When the subnet mask includes between 9 and 16 subnet bits, subnetting spans across **two octets** (typically the 3rd and 4th).  

**Steps:**

1. Calculate the subnet IDs as you would for fewer than 8 bits.  
2. When the total reaches 256 in the rightmost octet, move one octet to the left and increment it by 1 — this begins a **new subnet block**.  
3. Repeat this process until the octet reaches **255**.

This creates multiple subnet blocks, each representing a new range of subnet IDs.

---

### Subnets with 17 or More Subnet Bits

For subnet masks with 17 or more subnet bits, the network is necessarily a **Class A** network.  

The same logic applies as with 9–16 bits, but across additional octets. You effectively generate subnet blocks for **all combinations of the second and third octets** (0–255 each).  

This approach systematically defines every possible subnet within the Class A address space.
