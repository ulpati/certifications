## LAN Switching Concepts

### Overview of Switching Logic
A **LAN switch** operates by efficiently forwarding Ethernet frames within a network. Its primary responsibilities include:

1. **Forwarding or filtering frames** based on the destination MAC address.  
2. **Learning source MAC addresses** to build a forwarding table for future use.  
3. **Preventing loops** by coordinating with other switches through the **Spanning Tree Protocol (STP)**.

---

### Forwarding Known Unicast Frames
A switch maintains a **MAC address table** (also known as a *switching table*, *bridging table*, or *Content Addressable Memory (CAM) table*) that maps MAC addresses to specific interfaces.  

When a frame arrives, the switch checks its **destination MAC address** in this table:
- If the destination is known, it **forwards the frame** through the corresponding port.  
- If not, it may **flood** the frame (discussed later).  

Each switch independently makes forwarding decisions based on its own table. Frames with known destinations are called **known unicast frames**.

---

### Learning MAC Addresses
Switches **dynamically learn** MAC addresses by inspecting the **source MAC address** of incoming frames.  
When a frame arrives:
- The switch records the source MAC and the port it came from.
- This information is stored in the MAC address table for future forwarding decisions.

---

### Flooding Unknown Unicast and Broadcast Frames
If a frame’s destination MAC address is **unknown**, the switch performs **flooding**—sending the frame out of all interfaces except the one it came in on.  
Such frames are known as **unknown unicast frames**.  

Similarly, **broadcast frames** (those sent to `FF:FF:FF:FF:FF:FF`) are always flooded to all ports.

---

### Avoiding Loops with the Spanning Tree Protocol (STP)
Without control, Ethernet switches could create **Layer 2 loops**, causing repeated flooding that can cripple a network.  

To prevent this, the **Spanning Tree Protocol (STP)** ensures that only **one active path** exists between any two LAN segments by placing redundant ports into a **blocking** state.  

This enables fault tolerance while ensuring a loop-free topology.

## Verifying and Analyzing Ethernet Switching

By default, Cisco switches are preconfigured with several behaviors:
- All interfaces are **enabled** once a cable is connected.  
- All ports are assigned to **VLAN 1**.  
- 10/100 and 10/100/1000 interfaces use autonegotiation to determine speed and duplex settings.
- **MAC learning, forwarding, and flooding** are enabled.  
- **STP** is enabled.  

---

### Demonstrating MAC Learning
- `show mac address-table` → Displays the switch’s MAC address table  
- `show mac address-table dynamic` → Displays only dynamically learned MAC addresses


Output columns typically include:

- **VLAN**
- **MAC Address**
- **Type** (Static/Dynamic)
- **Port**

Frames are forwarded only within the same VLAN.
For example, frames arriving on VLAN 1 are only sent out through other ports in VLAN 1.

---

#### Checking Switch Interfaces

- `show interface status` → Verifies the status of all switch interfaces  
- `show interfaces f0/1 status` → Checks the status of a specific interface (FastEthernet 0/1)  
- `show interfaces f0/1` → Displays detailed information about a specific interface (FastEthernet 0/1)

Output columns typically include:

- **Port**
- **Name**
- **Status**
- **VLAN**
- **Duplex**
- **Speed**
- **Type**

---

- `show interfaces f0/1 counters` → Displays traffic statistics for a specific interface (FastEthernet 0/1)

---

#### Searching the MAC Address Table

You can filter and search MAC address table entries using several parameters:
| Purpose                              | Command Example                                        |
| ------------------------------------ | ------------------------------------------------------ |
| Search by MAC address                | `show mac address-table address <MAC>`                 |
| Show learned MACs on a specific port | `show mac address-table dynamic interface <interface>` |
| Display entries for a VLAN           | `show mac address-table vlan <VLAN_NUMBER>`            |


---

#### Managing the MAC Address Table (Aging and Clearing)

MAC address entries are **not permanent**. Switches remove them automatically after a period of inactivity or when the table becomes full.

**Default aging time**: 300 seconds

Each time a frame with the same source MAC is seen, the timer resets.

**Managing aging time:**
| Command                                       | Description                                      |
| --------------------------------------------- | ------------------------------------------------ |
| `mac address-table aging-time <seconds>`      | Sets the MAC address table aging time globally   |
| `mac address-table aging-time <seconds> vlan <vlan_number>` | Sets the aging time for a specific VLAN          |
| `show mac address-table aging-time`            | Displays the current aging time settings          |

---

To check the total number of learned MAC addresses:

| Command                             | Description                                      |
| ---------------------------------- | ------------------------------------------------ |
| `show mac address-table count`     | Displays the total number of learned MAC addresses |

---

If the MAC address table becomes full, the switch automatically removes the oldest entries, even if they haven’t reached the aging limit.

**Clearing entries manually:**

| Command                                               | Description                          |
| ----------------------------------------------------- | ----------------------------------- |
| `clear mac address-table dynamic`                     | Clears all dynamically learned entries |
| `clear mac address-table dynamic vlan <vlan_number>` | Clears dynamic entries for a specific VLAN |
| `clear mac address-table dynamic interface <interface>` | Clears dynamic entries for a specific interface |
| `clear mac address-table dynamic address <MAC>`      | Clears a specific dynamic MAC address entry |
