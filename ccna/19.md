## Dynamic Host Configuration Protocol (DHCP)

DHCP simplifies IP address management by automatically assigning network parameters to devices. Rather than manually configuring each host, a **DHCP server** provides IP information to clients through a lease process — typically temporary, allowing efficient use of available addresses.

---

### DHCP Process Overview

DHCP communication occurs in **four main steps**, known as the **DORA** process:

| Step | Message | Description |
|------|----------|-------------|
| 1 | **Discover** | The client broadcasts a message to locate available DHCP servers. |
| 2 | **Offer** | A DHCP server responds with an IP address offer and additional configuration details. |
| 3 | **Request** | The client requests the offered IP address from the chosen server. |
| 4 | **Acknowledgment** | The server confirms and finalizes the lease, providing the IP address, subnet mask, default gateway, and DNS information. |

---

### IP Addresses Used During DHCP Negotiation

Because a client initially has no IP address, DHCP uses special IP addresses:

- **0.0.0.0** → Temporary source address used by clients before an IP is assigned.  
- **255.255.255.255** → Limited broadcast destination address used so the DHCP messages can reach servers on the same network segment.

The client identifies itself with a **Client ID**, which includes its **MAC address**. This ensures that only the intended client accepts the DHCP offer message.

---

### APIPA (Automatic Private IP Addressing)

If a host fails to obtain an address from a DHCP server, it can self-assign an address in the **169.254.0.0/16** range. This feature, known as **APIPA**, enables local communication even without a DHCP server.

#### How APIPA Works

1. The host selects an IP address between `169.254.1.0` and `169.254.254.255`.  
2. The host uses **ARP** to ensure no other device on the LAN is using the same address (**Duplicate Address Detection**).  
3. If the address is unique, it is assigned to the host.  
4. The host can now communicate **only within the local subnet**.

---

### DHCP Relay for Remote Subnets

In larger networks, DHCP servers are often centralized. Routers on remote subnets must forward DHCP broadcasts using the **DHCP relay** feature, configured with: `ip helper-address <server_ip>`

#### How DHCP Relay Works
When a router receives a broadcast DHCP request:
- It detects DHCP packets (destination 255.255.255.255).
- The router replaces the **source IP** with its own interface IP.
- It sets the **destination IP** to the DHCP server address.
- The router then forwards the packet to the DHCP server.

This mechanism allows DHCP messages to traverse routed networks.

---

### Information Maintained by the DHCP Server

A DHCP server maintains configuration details for each subnet it serves:
- **Subnet ID and Mask** – Defines the subnet boundaries.
- **Excluded Addresses** – Prevents leasing of reserved static addresses (e.g., routers, printers).
- **Default Router** – Specifies the gateway for the subnet.
- **DNS Server(s)** – Provides name resolution addresses.
- **Lease Time and Optional Settings** – May include TFTP server addresses or extended lease durations.

DHCP supports three allocation types:
| Mode                     | Description                                                    |
| ------------------------ | -------------------------------------------------------------- |
| **Dynamic Allocation**   | Leases IPs temporarily, reclaiming them when no longer in use. |
| **Automatic Allocation** | Permanently assigns an IP to a device (infinite lease).        |
| **Static Allocation**    | Binds a specific IP to a specific MAC address.                 |

## Configuring DHCP on Cisco Devices

### Configuring DHCP Relay

Enable DHCP relay on router interfaces connected to client subnets where no DHCP server exists:
```
interface GigabitEthernet0/1
ip helper-address <server_ip>
```

Verify with: `show ip interface <interface_name>`

Look for: `Helper address is <server_ip>`

---

### Configuring a Switch as a DHCP Client

Although not common in production, you can configure a switch to obtain its management IP dynamically:
```
interface vlan <vlan_id>
ip address dhcp
```

Verification commands:
```
show interfaces vlan <vlan_id>
show dhcp lease
```

The first shows the current IP configuration; the second provides lease details and parameters.

---

### Configuring a Router as a DHCP Client

Routers connecting to ISPs often act as DHCP clients to receive their public IP and default route automatically:
```
interface GigabitEthernet0/0
ip address dhcp
```

The router learns the **IP address**, **subnet mask**, and **default gateway** (from the ISP).
This default route appears as a **static route** with an **administrative distance of 254**.

### Identifying Host IPv4 Settings

Every host OS includes tools for viewing and troubleshooting IP configurations.

#### Host IP Commands on Windows

| Command                          | Purpose                                                    |
| -------------------------------- | ---------------------------------------------------------- |
| `ipconfig`                       | Displays basic IP configuration.                           |
| `ipconfig /all`                  | Shows detailed settings including DNS and DHCP lease info. |
| `netsh interface ip show config` | Lists interface-specific IP configurations.                |
| `netstat -rn`                    | Displays the routing table.                                |
| `netsh interface ip show route`  | Another way to view routing information.                   |

---

#### Host IP Commands on macOS

| Command                             | Purpose                                          |
| ----------------------------------- | ------------------------------------------------ |
| `ifconfig [interface]`              | Displays interface configuration details.        |
| `networksetup -getinfo <interface>` | Shows IP settings for a given network interface. |
| `netstat -rn`                       | Displays routing table entries.                  |

#### Host IP Commands on Linux

| Command                | Purpose                                                       |
| ---------------------- | ------------------------------------------------------------- |
| `ifconfig [interface]` | Shows interface details (older command).                      |
| `ip address`           | Displays IP address configuration (preferred modern command). |
| `netstat -rn`          | Shows routing table entries.                                  |
| `ip route`             | Displays and manages the routing table.                       |

**Tip**: On modern Linux systems, the `ip` suite (`ip addr`, `ip route`, `ip link`) replaces most legacy networking commands for better control and output consistency.
