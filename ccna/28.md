## Understanding the Neighbor Discovery Protocol (NDP)

IPv6 introduces the **Neighbor Discovery Protocol (NDP)**, which performs several vital roles that replace or expand on IPv4 mechanisms like ARP and ICMP Router Discovery.  
Here are NDP’s key functions:

- **Neighbor MAC Discovery:** Replaces IPv4’s ARP by allowing a host to learn the MAC address of another host in the same subnet.  
- **Router Discovery:** Enables hosts to find routers on the same link.  
- **Prefix Discovery:** Allows hosts to learn the subnet prefix and prefix length in use on the network.  
- **Duplicate Address Detection (DAD):** Ensures that no two hosts use the same IPv6 address on the same link.

---

### Discovering Neighbor Link Addresses with NDP (NS and NA)

NDP substitutes ARP with two main message types:

- **Neighbor Solicitation (NS):** A host sends this message to ask for the MAC address of another device with a known IPv6 address.  
- **Neighbor Advertisement (NA):** The reply message, which includes both the IPv6 and MAC addresses of the sender. It can be sent in response to an NS or proactively (unsolicited) to the multicast address `FF02::1` to announce the host’s presence.

> 💡 In NDP, the term *neighbor* refers to another device on the **same data link**.

#### Viewing the NDP Neighbor Table

| OS | Command |
|----|----------|
| **Windows** | `netsh interface ipv6 show neighbors` or PowerShell: `Get-NetNeighbor -AddressFamily IPv6` |
| **Linux** | `ip -6 neighbor show` |
| **macOS** | `ndp -an` |

---

### Discovering Routers with NDP (RS and RA)

NDP also handles router discovery through two message types:

- **Router Solicitation (RS):** Hosts send this message to `FF02::2` (the all-IPv6-routers multicast address) to ask routers to identify themselves.  
- **Router Advertisement (RA):** Routers respond to RS messages — or send unsolicited RA messages periodically — to `FF02::1` (the all-IPv6-hosts multicast address).  
  These RAs contain router addresses, prefixes, and other configuration information.

> To view routers learned by a host:  
> - **Windows:** `netsh interface ipv6 show neighbors`  
> - **Linux:** `ip -6 neighbor`  
> - **macOS:** `ndp -rn`

---

### Learning Prefixes with Router Advertisements

RA messages do more than list routers—they also advertise the IPv6 **prefixes** used on the local link. Hosts then:
1. Create a route for each on-link prefix, allowing direct communication with local devices.  
2. Build a **default route** pointing to the router’s **link-local address (LLA)**, enabling off-link communication.

---

### Detecting Duplicate Addresses (DAD)

When a host selects or is assigned an IPv6 address, it must ensure uniqueness using **Duplicate Address Detection (DAD)**.  
The host sends an NS message for its own address; if another device responds with an NA, the host detects a conflict and does not use that address.

## Dynamic Configuration of Host IPv6 Settings

IPv6 introduces two main ways to automatically assign IP addresses to hosts:

1. **Stateful DHCPv6** – The server tracks address leases (similar to DHCP for IPv4).  
2. **Stateless Address Autoconfiguration (SLAAC)** – The host configures its own address without needing a DHCP server.

---

### Using Stateful DHCPv6

This approach works much like DHCPv4:
- Clients broadcast requests within their LAN to find a DHCPv6 server.  
- If the server is on another subnet, a **router configured as a relay agent** forwards the messages.  
- The server maintains a list of address pools and tracks which addresses are leased to which clients.  

A **stateful DHCPv6 server** stores this **state information**, identifying which host owns which IPv6 address.

#### Key Differences Between DHCPv4 and DHCPv6
While DHCPv6 still assigns IP addresses and DNS information, hosts also rely on NDP’s Router Advertisement messages for:
- Default router address  
- Prefix length and routing details  

DHCPv6 messages use **Solicit, Advertise, Request, and Reply**, instead of IPv4’s **Discover, Offer, Request, and Acknowledge**.

#### Configuring a DHCPv6 Relay Agent
When the DHCP server is not on the same subnet, configure the router as a relay with:
```
ipv6 dhcp relay destination <IPv6_address_of_DHCP_server>
```

The client sends packets from its **link-local address** to the multicast group **FF02::1:2** (all-DHCP-agents).

---

### Stateless Address Autoconfiguration (SLAAC)

SLAAC allows a host to automatically configure its IPv6 address without relying on a DHCP server.

#### Steps for SLAAC Configuration

1. Learn the IPv6 prefix and prefix length from a router’s RA message.
2. Generate the **interface ID (IID)** — often using **EUI-64** or a random method.
3. Perform **DAD** to verify address uniqueness before using it.

#### Combining SLAAC with Stateless DHCPv6

SLAAC can work together with **Stateless DHCPv6** to provide additional settings such as DNS servers.

| Feature                         | Stateful DHCPv6 | Stateless DHCPv6 |
| ------------------------------- | --------------- | ---------------- |
| Tracks client addresses (state) | ✅ Yes           | ❌ No             |
| Assigns IPv6 addresses          | ✅ Yes           | ❌ No             |
| Provides DNS information        | ✅ Yes           | ✅ Yes            |
| Works with SLAAC                | ❌ No            | ✅ Yes            |

Stateless DHCPv6 servers are simpler — they provide configuration details like DNS addresses but don’t manage leases or per-subnet settings.

---

### Router-Advertised DNS Configuration (RDNSS)

Instead of using a DHCPv6 server, routers can directly advertise DNS server addresses in their **Router Advertisement messages**.
This method allows complete host configuration using only router settings — no DHCP servers required.

---

### Permanent and Temporary SLAAC Addresses

When using SLAAC, a host can generate:

* A **permanent address**, used for consistent identification (e.g., servers).
* One or more **temporary addresses**, used for outgoing client connections to improve privacy.

Each address has a **preferred** and **valid lifetime**:

* During the **preferred** period, it can be used for new connections.
* During the **valid** period, it remains usable for existing sessions.
* After expiration, the address becomes **deprecated** and is not reused.

#### Viewing SLAAC Addresses

| OS          | Command                                                |
| ----------- | ------------------------------------------------------ |
| **macOS**   | `ifconfig en0 inet6` or `ifconfig -aL inet6`           |
| **Linux**   | `ip -6 address`                                        |
| **Windows** | `ipconfig /all` or `netsh interface ipv6 show address` |

## Troubleshooting IPv6 on Hosts

### Testing IPv6 Connectivity

The tools remain similar to IPv4:

* **Windows & Cisco:** `ping` and `traceroute`
* **Linux & macOS:** `ping6` and `traceroute6`

> The `traceroute` commands use ICMPv6 *Time Exceeded* messages to map the path through intermediate routers.

---

### Verifying Host Reachability from a Router

Routers can confirm host connectivity using NDP:

1. Clear the NDP neighbor table:

   ```
   clear ipv6 neighbor
   ```
2. Ping the host.
   The router sends an **NS** message and waits for an **NA** in response.
   If the neighbor table now lists the host’s MAC address, the host has replied successfully.
