## Introduction

Computer networks function effectively thanks to **standards** and **protocols**.  
Networking models provide a structured framework of layers, each defining specific protocols, responsibilities, and how those layers interact with one another.  

Among all existing models, **TCP/IP** is the most widely used, and it is the primary focus of the **CCNA certification**.

---

## Overview of the TCP/IP Networking Model

The **TCP/IP model** defines networking protocols through documents known as **Requests for Comments (RFCs)**. These documents describe how each protocol operates and interacts within the model.

### TCP/IP Model Layers

| **Layer** | **Description** |
|------------|-----------------|
| **Application** | Determines what data to request, how to request it, and how to present it to the user or software. |
| **Transport** | Ensures reliable delivery of data and manages transmission errors. |
| **Internet** | Handles data delivery across an entire path or network. |
| **Data Link** | Defines the rules for accessing and using the physical link. |
| **Physical** | Describes how bits are transmitted across the physical medium. |

---

## TCP/IP Application Layer

> **Examples:** HTTPS, POP3, SMTP  

The **Application layer** provides services for application software, serving as an **interface** between running programs and the network.  
It does **not** define the applications themselves, but rather how they communicate over the network.

### Example: HTTP Protocol Mechanism

When retrieving a web page from a server:

1. The client sends an **HTTP GET request** to the web server.  
2. If successful, the server replies with a **200 OK** response and delivers the requested webpage.

Most protocols include **headers**, which store metadata and control information essential for communication.

---

## TCP/IP Transport Layer

> **Examples:** TCP, UDP  

The **Transport layer** provides communication services for application layer protocols, ensuring reliable or best-effort data transfer as needed.

### Same-Layer and Adjacent-Layer Interactions

To better understand these concepts, consider how **TCP** manages error recovery.

When a web server sends a webpage, it divides the content into **segments**, each labeled with a **sequence number (SEQ)**.  
If one of these segments is lost during transmission, the client can request its retransmission.

- **Same-layer interaction** occurs when the **Transport layer** on one device communicates with the same layer on another device, using headers  to manage data transfer.  
- **Adjacent-layer interaction** happens between **layers on the same device**. For instance, when HTTP requires reliable delivery, it relies on TCP to handle retransmissions and acknowledgments.

---

## TCP/IP Internet Layer

> **Examples:** IP, ICMP  

The **Internet layer** is responsible for **addressing**, **routing**, and **delivering data** across interconnected networks.

### IP Addressing Basics

Every device using TCP/IP must have a **unique IP address**, allowing it to be identified and reached within a network.

### IP Routing Basics

Routing involves **forwarding IP packets** from one device to another until they reach their final destination.

Using the same web page example:
1. The server adds an **IP header** with source and destination IP addresses.  
2. The server sends the packet to a nearby **router**.  
3. The router compares the destination address with its **routing table** and forwards the packet toward the correct path.  
4. The **final router**, closest to the PC, delivers the packet to its destination.

---

## TCP/IP Data Link and Physical Layers

> **Examples:** Ethernet, IEEE 802.11 (Wi-Fi)

The **Data Link** and **Physical** layers define the hardware and protocols used to transmit data across physical media.

When a server sends a packet to a nearby router:

1. The server **encapsulates** the IP packet with an **Ethernet header and trailer**, forming an **Ethernet frame**.  
2. The server **transmits the bits** physically over the cable or wireless link.  
3. The router **receives the bits**, reconstructs the frame, and **removes** the Ethernet header and trailer to extract the IP packet.

---

## Data Encapsulation Terminology

**Encapsulation** is the process of wrapping data with headers (and sometimes trailers) as it moves through the network layers.

The typical encapsulation sequence for sending data over TCP/IP is:

1. Create and encapsulate **application data** with any required application headers.  
2. Encapsulate that data within a **transport layer header**.  
3. Add an **internet layer header** to the transport segment.  
4. Add **data-link layer headers and trailers**.  
5. **Transmit the bits** over the physical medium.

---

## Names of TCP/IP Messages

Each layer of the TCP/IP model defines its own terminology for data units:

| **Name** | **Layer** |
|-----------|------------|
| **Segment** | Transport Layer |
| **Packet** | Internet Layer |
| **Frame** | Data Link Layer |

The term **Protocol Data Unit (PDU)** can be used to refer to any message defined by a protocol.
