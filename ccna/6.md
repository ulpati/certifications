## Securing the Switch CLI

### Securing User and Privileged Modes with Basic Passwords
Switches use two access levels in the CLI:  
- **User EXEC mode (user mode)** for basic monitoring  
- **Privileged EXEC mode (enable mode)** for configuration and management

You can protect both levels with passwords.

**Set a console password (user mode):**
```
line console 0
login
password <password>
```

**Set a Telnet password (remote user mode):**
```
line vty 0 15
login
password <password>
transport input all
```

**Set an enable (privileged mode) password:**
```
enable password <password>
```
or encrypted
```
enable secret <password>
```

**Encrypt all passwords**:
```
service password-encryption
```

---

### Securing User Mode Access with Local Usernames and Passwords
Instead of a single shared password, you can configure **individual local users**:
```
username <username1> secret <password1>
username <username2> secret <password2>
```

**Console access using local authentication:**
```
line console 0
login local
no password   # Optional – removes any previous console password
```

**Telnet access using local authentication:**
```
line vty 0 15
login local
no password   # Optional
transport input all
```

When a user exits configuration mode, the switch logs the event — a useful security measure for tracking changes.

---

### Securing User Access with External Authentication Servers (AAA)
Instead of relying on local credentials, Cisco switches can integrate with **AAA servers** (Authentication, Authorization, and Accounting) for centralized login management.

The two most common Cisco-supported protocols are:
- **RADIUS** – combines authentication and authorization in one process, commonly used for network access control.

- **TACACS+** – separates authentication, authorization, and accounting, offering more granular control, especially in enterprise environments.

These servers verify user credentials and apply appropriate permissions, improving scalability and security across multiple devices.

### Securing Remote Access with SSH
**SSH (Secure Shell)** encrypts all traffic, providing secure remote access to the switch — unlike Telnet, which transmits data in plain text.
SSH requires a hostname and domain name to generate RSA keys.

```
hostname <hostname>
ip domain name <domain_name>
crypto key generate rsa
ip ssh version 2   # Optional but recommended
line vty 0 15
login local
transport input all
```

**Transport input options:**
- `transport input all` – allows both Telnet and SSH
- `transport input none` – disables both
- `transport input telnet` – enables Telnet only
- `transport input ssh` – enables SSH only

**Verification commands:**
```
show ip ssh    # Displays SSH server status
show ssh       # Lists active SSH client sessions
```

### Enabling and Securing the WebUI
Cisco switches include a Web User Interface (WebUI) for management.
To secure it:
```
no ip http server   # Disables the unsecured HTTP service.
ip http secure-server   # Enables HTTPS
ip http authentication local    # Ensures login requires a local username/password.
username <username> privilege 15 password <password>
```

**Privilege levels:**
Cisco IOS uses privilege levels from 0 to 15.
- **Level 0**: Minimal access (only basic commands like `logout` or `enable`).
- **Level 1**: User EXEC mode — allows basic monitoring.
- **Level 15**: Privileged EXEC mode — grants full administrative control.

Therefore, setting privilege level **15** allows full management access via the WebUI.

## Enabling IPv4 for Remote Access

### Host and Switch IP Settings
A switch uses a **Switch Virtual Interface (SVI)**, also called a **VLAN interface**, for IP configuration.
This allows Layer 3 communication between the switch and other devices within the VLAN.
```
interface vlan <number>
ip address <ip_address> <subnet_mask>
```

To communicate outside the local subnet, configure a default gateway—typically the IP address of the local router.

---

### Configuring IPv4 on a Switch
```
configure terminal
interface vlan <number>
ip address <ip_address> <subnet_mask>
no shutdown   # Enables the interface administratively
exit
ip default-gateway <ip_address>
```

---

### Configuring a Switch to Learn Its IP Address via DHCP
If DHCP is available on the network, the switch can automatically obtain its IP configuration:
```
configure terminal
interface vlan <number>
ip address dhcp
no shutdown
```

---

### Verifying IPv4 Configuration
Useful commands for validation:
```
show running-config        # Displays current configuration
show interfaces vlan <n>   # Shows IP and mask details
show dhcp lease            # Displays the leased IP address
```

## Useful Commands and Operational Settings

### History Buffer Commands

The **history buffer** stores recently used commands.
```
show history                      # Displays command history
terminal history size <number>    # Sets buffer size for current session
history size <number>             # Sets default buffer size globally
```

Increasing the history buffer helps recall previous commands during long configuration sessions.

----

### Logging Synchronous
By default, the console displays unsolicited **syslog messages**, which can interrupt command typing.
You can control this behavior using:
```
no logging console     # Disable console logging
logging console        # Enable it again
```

To make messages appear more cleanly (after your command output), enable:
```
logging synchronous
```

Other helpful session management commands:
```
exec-timeout <minutes> <seconds>   # Sets inactivity timeout (0 0 disables it)
no ip domain-lookup                # Prevents IOS from trying to resolve mistyped commands
```

Example: Typing an invalid command may trigger a DNS lookup and cause delays; disabling domain lookup avoids this issue.
