## Implementing OSPFv2 Using `network` Commands  

Open Shortest Path First (OSPF) is a link-state routing protocol used to dynamically share routing information between routers. Implementing OSPF involves configuring routers to identify themselves, participate in an OSPF process, and advertise the correct networks.

### Step-by-Step Configuration  

1. **Start OSPF Configuration**  
   Enter OSPF configuration mode for a specific process using: `router ospf <process_id>`

   Each process ID is local to the router and does not need to match other routers in the same area.

2. **Define the Router ID (Optional)**  
The Router ID (RID) uniquely identifies the router within an OSPF domain. It can be chosen in one of three ways:
- Manually set with:
  ```
  router-id <id_value>
  ```
- Automatically use the **highest IP address** of any loopback interface.
- Otherwise, use the **highest active IP address** on any physical interface.

3. **Enable OSPF on Interfaces**  
Use the `network` command to associate interfaces with an OSPF area: `network <ip_address> <wildcard_mask> area <area_id>`

    Any interface whose IP address matches the network and wildcard mask becomes an OSPF-enabled interface for the specified area.

---

## Understanding the `network` Command and Wildcard Masks  

The **wildcard mask** tells IOS which parts of an IP address to match.  
- A `0` bit means “compare this part,” while a `255` means “ignore this part.”  

Examples:  
| Wildcard Mask | Meaning | Example Comparison |
|----------------|----------|--------------------|
| 0.0.0.0 | Match the exact IP | All octets must match |
| 0.0.0.255 | Match the first three octets | Matches /24 subnet |
| 0.0.255.255 | Match first two octets | Matches /16 subnet |
| 255.255.255.255 | Match nothing | Matches all addresses |

This flexibility lets administrators quickly enable OSPF on multiple interfaces without listing each one individually.

## Verifying OSPF Operations  

Routers go through a three-stage process when building their OSPF routing tables:  
1. **Forming Neighbor Relationships**  
2. **Exchanging LSAs (Link-State Advertisements)**  
3. **Running SPF (Shortest Path First) to Choose Best Routes**  

Useful commands:  
- `show ip ospf neighbor` – Displays OSPF neighbor states  
- `show ip ospf database` – Displays the link-state database  
- `show ip route` – Verifies OSPF-learned routes  

### Common Neighbor States  

| State | Description |
|--------|--------------|
| FULL/- | Fully adjacent, no DR/BDR election needed |
| FULL/DR | Neighbor is the Designated Router |
| FULL/BDR | Neighbor is the Backup Designated Router |
| FULL/DROTHER | Local router is DR/BDR; neighbor is neither |
| 2WAY/DROTHER | Two-way communication between non-DR routers |

## Troubleshooting OSPF Configurations  

If OSPF doesn’t appear to work as expected, verify your setup:  
- `show running-config` – Check OSPF configuration details  
- `show ip protocols` – View routing protocol summary  
- `show ip ospf interface [brief]` – Confirm OSPF is enabled on the correct interfaces

## Configuring the OSPF Router ID  

When a router initializes OSPF, it determines its **Router ID (RID)** using this order:  
1. Manually configured `router-id` command.  
2. Highest IP address among **loopback interfaces**.  
3. Highest IP address among **active interfaces**.  

> 🔹 *Note:* The Router ID remains fixed after initialization. If it changes, all neighbor relationships reset, and OSPF routes are recalculated. For a stable OSPF network, manually configure the RID or use a loopback interface.

Loopback interfaces are virtual and always in an **up/up** state unless administratively shut down:
```
interface loopback <number>
ip address <address> <mask>
```

## Implementing OSPFv2 Using Interface Subcommands  

Instead of using `network` commands, you can enable OSPF directly on interfaces:  
```
interface <type> <number>
ip ospf <process_id> area <area_id>
```


This approach provides **more precise control** because OSPF is explicitly activated per interface.

### Priority Rules  

If both a `network` command and an `ip ospf` interface command enable OSPF on the same interface:
- The **area ID defined under the interface** takes precedence.
- If multiple `network` commands match the same interface, IOS uses the **first match** in configuration order.

This configuration method is especially useful in large or complex networks where precise OSPF behavior per interface is desired.
