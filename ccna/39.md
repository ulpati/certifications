## Protecting Cisco IOS Passwords

The most effective method for protecting passwords on Cisco IOS devices is **not to store them locally**. Whenever possible, authentication should be managed through an external **AAA (Authentication, Authorization, and Accounting)** server.

---

### Encrypting Legacy IOS Passwords with `service password-encryption`

The `service password-encryption` command encrypts passwords that would otherwise appear in clear text. This applies to passwords defined in:

- `password <password>` (console or VTY mode)  
- `username <name> password <password>` (global configuration)  
- `enable password <password>` (global configuration)

When enabled, IOS adds an encryption type **“7”** to these passwords, indicating they have been encoded with the `service password-encryption` method (type “0” represents plain text).  

However, this method offers **very weak protection** — encrypted passwords can easily be decoded using publicly available tools. The `no service password-encryption` command stops future encryption but does not decrypt existing entries.

> ⚠️ **Recommendation:** Avoid relying on this feature for serious security. Use stronger alternatives like the `enable secret` command instead.

---

### Strengthening Enable Passwords with Hashing

Cisco introduced the `enable secret` command as a **secure replacement** for the older `enable password` command.  
The `enable secret` command stores passwords using **cryptographic hash functions**, which are much harder to reverse.

#### Enable Password vs Enable Secret

Here’s how the two commands interact:

- **Both configured:** IOS always uses the `enable secret` password.  
- **Only one configured:** The available one is used.  
- **Neither configured:** Console users can enter privileged EXEC mode without a password; remote users (Telnet/SSH) are denied.

#### How the Enable Secret Works

By default, the `enable secret` command uses the **MD5 hashing algorithm (type 5)**. Instead of storing the password itself, IOS stores the **hash value** generated by the MD5 algorithm.

When a user enters a password, IOS hashes it and compares the result with the stored hash.  
If both match, access is granted. Since MD5 hashing is a one-way function, the original password cannot be recovered from the hash.

#### Modern Hash Algorithms

Cisco later added stronger hashing options to the `enable secret` command:

| Command | Type | Algorithm |
|----------|------|-----------|
| `enable algorithm-type md5 secret <password>` | 5 | MD5 |
| `enable algorithm-type sha256 secret <password>` | 8 | SHA-256 |
| `enable algorithm-type scrypt secret <password>` | 9 | Scrypt |

Only **one enable secret** can exist at a time. Configuring a new one replaces the previous entry.

> **Defaults:**  
> IOS uses **MD5** by default, while **IOS XE** defaults to **Scrypt**, offering greater resistance to brute-force attacks.

---

### Encoding Passwords for Local User Accounts

Local user accounts are configured directly on the router or switch using the `username` command.  
For stronger protection, Cisco introduced the **`username <name> secret <password>`** command, which stores passwords as hashes instead of plain text.

#### Key Rules

- Each username can only have **one password definition**, either `username password` or `username secret`.  
- IOS allows a **mix** of these commands for different users.

#### Supported Hash Algorithms

| Command | Type | Algorithm |
|----------|------|-----------|
| `username <name> algorithm-type md5 secret <password>` | 5 | MD5 |
| `username <name> algorithm-type sha256 secret <password>` | 8 | SHA-256 |
| `username <name> algorithm-type scrypt secret <password>` | 9 | Scrypt |

As with the `enable secret` command, IOS uses **MD5** by default, while IOS XE defaults to **Scrypt**.  
Note that IOS XE **no longer supports MD5** for local username hashing due to its vulnerabilities.

## Firewalls and Intrusion Prevention Systems (IPS)

### Traditional Firewalls

A **firewall** acts as a security barrier between network segments, analyzing traffic to decide whether to allow or block it based on defined rules.  
While similar to router ACLs, firewalls provide **deeper packet inspection and stateful analysis**, allowing them to identify patterns and behaviors that routers cannot.

Firewalls can inspect packets using multiple criteria:
- Source and destination IP addresses  
- TCP/UDP port numbers  
- Application-layer traffic (to detect dynamic or secondary connections)  
- URL and HTTP header content  
- Stateful tracking of established sessions

#### Stateful Inspection

Unlike basic ACLs, a **stateful firewall** maintains session information — tracking the state and context of network connections.  
This enables it to detect anomalies such as **DoS attacks** by monitoring traffic rates and recognizing unusual patterns, such as an excessive number of TCP SYN requests from a small number of sources.

A stateless device (like a router ACL) cannot correlate this historical data, leaving it unable to detect such attacks effectively.

---

### Security Zones

Firewalls categorize network interfaces into **security zones**, defining which zones can initiate or receive traffic.  

Common setups include:
- **Inside zone:** Trusted internal network.  
- **Outside zone:** Untrusted external (e.g., Internet).  
- **DMZ (Demilitarized Zone):** Hosts public-facing services like web or mail servers.

Placing servers in a DMZ isolates them from the internal network, minimizing exposure if they are compromised.  
By default, firewalls **block all traffic** unless explicitly allowed by a rule.

---

### Intrusion Prevention Systems (IPS)

An **IPS** inspects network traffic in real-time to detect and stop malicious activity.  
It uses a **database of signatures** — patterns that identify known attacks — to identify threats such as DoS, DDoS, worms, or viruses.

When a match occurs, the IPS can:
- Log the event  
- Drop the packet  
- Redirect traffic for deeper analysis

IPS devices typically operate **inline**, meaning they directly process live traffic and can immediately block malicious packets.

## Cisco Next-Generation Security Solutions

### Cisco Next-Generation Firewalls (NGFW)

Cisco’s **NGFW** platforms extend traditional firewall functionality with advanced, integrated security features:

- **Stateful Firewall Functions:** Full packet inspection, NAT/PAT, and VPN termination.  
- **Application Visibility and Control (AVC):** Identifies applications by analyzing data content instead of port numbers.  
- **Advanced Malware Protection (AMP):** Detects and blocks malicious files in real time, storing samples for later analysis.  
- **URL Filtering:** Categorizes and filters web traffic using Cisco Talos reputation scores.  
- **Integrated NGIPS:** Incorporates next-generation intrusion prevention capabilities.

---

### Cisco Next-Generation IPS (NGIPS)

The **NGIPS** builds upon traditional IPS functions, offering greater context and intelligence.

**Key Features:**
- **Signature-Based Detection:** Identifies traffic patterns matching known exploits.  
- **Application Visibility and Control (AVC):** Detects the actual application in use at Layer 7.  
- **Contextual Awareness:** Gathers host details (OS, version, open ports, applications) to prioritize real threats.  
- **Reputation-Based Filtering:** Uses Cisco Talos intelligence to block traffic from malicious domains, IPs, or URLs.  
- **Event Impact Levels:** Assesses and categorizes alerts by severity, helping security teams prioritize responses.
