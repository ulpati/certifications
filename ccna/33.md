## Connecting a Cisco Access Point (AP)

When connecting a Cisco Access Point (AP) to a switch, the switch port must be configured in **access** or **trunk** mode.  
- In **trunk mode**, the switch uses **802.1Q encapsulation** to tag frames with their VLAN identifiers.  
- On the wireless side, APs automatically associate frames with the appropriate WLAN using the **BSSID**.  

For **autonomous APs**, all VLANs must be carried over a trunk link to the Ethernet port. However, in **controller-based environments**, VLANs that terminate at the **Wireless LAN Controller (WLC)** can be mapped directly to WLANs—allowing APs to connect using a simple access link.

## Accessing a Cisco Wireless LAN Controller (WLC)

To manage a WLC, open a web browser and connect to its **management IP address** using **HTTP** or **HTTPS**.  
Before doing this, ensure the controller has:  
- A basic configuration  
- A valid management IP  
- An SSL certificate for secure HTTPS access  

The **WLC GUI** is the primary interface for configuring, monitoring, and troubleshooting the wireless network. You can also connect via **SSH** to access the command-line interface (CLI).  

In **IOS-XE**, navigate to **Configuration** from the left column.  
In **AireOS**, click the **Advanced** link in the upper-right corner.

## Connecting a Cisco WLC

### Physical Ports Overview

Cisco WLCs include several physical ports, each serving a specific purpose:

- **Console Port:** For initial setup and recovery.  
- **Service Port:** Used for out-of-band management via SSH or web GUI.  
- **Redundancy Port:** Connects to a peer controller for high availability.  
- **Ethernet Ports:** Carry CAPWAP tunnels and general network traffic.  

All Ethernet ports on IOS-XE and AireOS controllers must operate in **802.1Q trunk mode**. Switch ports connected to the controller should also be set to **trunk mode**.

For **resilience and load balancing**, controllers can group Ethernet ports into a **Link Aggregation Group (LAG)**—similar to an **EtherChannel**. If one port fails, traffic automatically reroutes to the remaining links.  

### VLANs, WLANs, and Interfaces

Although VLANs reach the controller through its Ethernet ports, **WLANs** terminate within the controller through **CAPWAP tunnels**.  
- **Dynamic interfaces** map WLANs to VLANs.  
- On **IOS-XE controllers**, these interfaces operate at **Layer 2** and do not require IP addressing.  
- On **AireOS controllers**, each dynamic interface must have an **IP address**, **subnet mask**, **default gateway**, and **DHCP server** defined.  

### Wireless Management Interface (WMI)

Both platforms require a **Wireless Management Interface (WMI)** for in-band management and CAPWAP tunnel termination.  
- On IOS-XE, the WMI is an **SVI** with a single IP address.  
- A **virtual interface** (e.g., `10.1.1.1`) handles client mobility and must be **identical across all controllers in a mobility group** to ensure seamless roaming.

## Configuring a Wireless LAN (WLAN)

A WLC and AP work together to deliver wireless connectivity.  
- **Access Points** broadcast an **SSID** for client association.  
- **Controllers** connect that SSID to a **VLAN** through a **dynamic interface**.  

To establish this link, you must create and bind a **WLAN** on the controller. Once defined, the configuration is pushed to all APs automatically.  

> **Note:** Cisco controllers support up to **512 WLANs**, but only **16** can be active per AP. Each additional WLAN consumes valuable **airtime**, so limit usage where possible.

Before creating a WLAN, identify:  
- SSID name  
- Associated VLAN/interface  
- Security type

## Configuring a WLAN on IOS-XE Controllers

IOS-XE controllers organize configuration into three main categories:

1. **Policy** – WLAN and security parameters  
2. **Site** – CAPWAP, AP relationships, and FlexConnect behavior  
3. **RF** – Radio settings for each frequency band  

Each category applies through **profiles and tags**.

### Step 1: Create a WLAN Profile
1. Navigate to **Configuration → Wireless Setup → WLANs**, then click **Start Now**.  
2. Select **+** next to *WLAN Profile*.  
3. On the **General** tab, enter a profile name and SSID, assign a WLAN ID, and enable broadcasting.  
4. Under **Security**, configure:  
   - **Layer 2:** WPA/WPA2  
   - **Layer 3:** Web authentication  
   - **AAA:** RADIUS, ISE, or LDAP settings  
5. Review the **Advanced** tab for additional options.  
6. Click **Apply to Device** to save.  

### Step 2: Create a Policy Profile
1. Select **+** next to *Policy Profile*.  
2. On the **General** tab, name and enable it.  
3. Under **Access Policies**, map the profile to a VLAN.  
4. Configure **QoS** and **Application Visibility & Control (AVC)** if needed.  
5. Click **Apply to Device** when done.  

### Step 3: Link Profiles via a Policy Tag
1. Go to **Tags & Profiles → Policy Tags**, then click **+**.  
2. Assign a name and optional description.  
3. Pair the WLAN profile with its corresponding policy profile.  
4. Add multiple WLANs if needed, then click **Apply to Device**.  

### Step 4: Apply Tags to Access Points
1. Open **Tags & Profiles → Tag APs**.  
2. Select APs from the list and assign the appropriate **Policy Tag**.  
3. Default tags include:  
   - `default-site-tag` → AP and Flex profiles  
   - `default-rf-tag` → Global RF settings  
   - `default-policy-tag` → No default WLAN mappings

## Configuring a WLAN on AireOS Controllers

### Step 1: Create a Dynamic Interface
1. Go to **Controller → Interfaces**, click **New**.  
2. Enter an interface name and VLAN ID.  
3. Configure **IP**, **subnet mask**, **gateway**, and **DHCP servers**.  
4. Click **Apply** to save.  

### Step 2: Create a WLAN
1. From the **WLANs** menu, select **Create New → Go**.  
2. Enter a **profile name** and **SSID**.  
3. Assign a **unique WLAN ID** (local to the controller).  
4. Click **Apply** to create the WLAN.  

### Step 3: Configure WLAN Parameters
1. Enable the WLAN by checking **Status**.  
2. Choose the desired **radio policy** and **dynamic interface**.  
3. Enable **Broadcast SSID** if you want the APs to advertise it.

## WLAN Security Configuration

Under the **Security** tab, select the appropriate **Layer 2 security method**:

| Option | Description |
|--------|--------------|
| None | Open authentication |
| WPA/WPA2 | Wi-Fi Protected Access |
| 802.1X | EAP authentication with dynamic WEP |
| Static WEP | Predefined key security |
| Static WEP + 802.1X | Combined authentication |
| CKIP | Cisco Key Integrity Protocol |
| None + EAP Passthrough | Open auth with remote EAP |

You can further define **WPA/WPA2/WPA3 methods** and specify **RADIUS servers** under **Security → AAA → RADIUS → Authentication**.

## Configuring WLAN Quality of Service (QoS)

Go to the **QoS tab** and choose one of the predefined profiles:

- **Platinum:** Voice  
- **Gold:** Video  
- **Silver:** Best Effort (default)  
- **Bronze:** Background traffic
