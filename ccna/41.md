## DHCP Snooping

### Understanding DHCP Snooping  

**DHCP Snooping** is a Layer 2 security feature designed to protect against malicious or unauthorized DHCP servers on a network. It works by analyzing incoming DHCP messages on specific switch ports within a VLAN. Although DHCP is a Layer 3 protocol, DHCP Snooping operates on Layer 2 switches and is typically enabled on Layer 2 interfaces.

The switch uses DHCP Snooping to distinguish between legitimate DHCP clients and servers. It decides whether to allow or block DHCP packets based on the port’s trust level:

- **Untrusted ports:** Drop DHCP messages that are typically sent by servers (e.g., `DHCPOFFER`, `DHCPACK`).
- **Trusted ports:** Forward all DHCP messages without restriction.
- **Client messages:** Messages such as `DHCPDISCOVER` or `DHCPREQUEST` are inspected for signs of spoofing or inconsistency before being allowed through.

In essence, DHCP Snooping ensures that only valid DHCP servers and clients exchange DHCP traffic, helping prevent IP address spoofing or rogue DHCP attacks.

---

### DHCP Snooping Logic  

DHCP Snooping monitors and filters all DHCP-related traffic as follows:

1. **Inspect every incoming DHCP message.**  
2. **Server-originated messages:**  
   - Discard if received on an *untrusted* port.  
3. **Client-originated messages:**  
   - **For `DISCOVER` and `REQUEST` messages:** verify that the MAC address in the Ethernet frame matches the `chaddr` (client hardware address) in the DHCP message.  
   - **For `RELEASE` or `DECLINE` messages:** ensure that the IP and interface match the entries in the DHCP Snooping binding table.  
4. **Build the DHCP Snooping binding table** when a valid DHCP lease is observed, recording the client’s IP address, MAC address, VLAN, and port.

This **binding table** becomes a trusted source of information for other switch security features, such as Dynamic ARP Inspection (DAI).

---

### Filtering DHCP DISCOVER Messages  

Each DHCP message includes the **client hardware address (chaddr)** field, which should match the **source MAC address** in the Ethernet frame. DHCP Snooping checks these two values.  
If they differ, the message is assumed to be malicious and is immediately discarded. This simple validation step prevents devices from pretending to be other clients.

---

### Filtering DHCP RELEASE Messages  

When a client releases its IP address, DHCP Snooping verifies that the IP address and port match the existing entry in the DHCP Snooping binding table. If they don’t, the switch drops the packet. This validation ensures that attackers cannot release or hijack IP addresses belonging to other devices.

---

### Configuring DHCP Snooping  

To configure DHCP Snooping on a Cisco switch:

1. **Enable DHCP Snooping globally:**  
   ```
   ip dhcp snooping
   ```

2. **Specify VLANs for DHCP Snooping:**

   ```
   ip dhcp snooping vlan <vlan-list>
   ```
3. **(Optional)** Disable Option 82 insertion (for Layer 2 switches not acting as DHCP relay agents):

   ```
   no ip dhcp snooping information option
   ```
4. **Trust specific interfaces (e.g., uplinks to DHCP servers):**

   ```
   interface <type/number>
   ip dhcp snooping trust
   ```
5. **(Optional)** Set rate limits to prevent DHCP flood attacks:

   ```
   interface <type/number>
   ip dhcp snooping limit rate <number>
   ```
6. **(Optional)** Configure automatic recovery for interfaces disabled due to rate-limit violations:

   ```
   errdisable recovery cause dhcp-rate-limit
   errdisable recovery interval <seconds>
   ```

**Verification:**
Use the following command to check the current configuration and status:

```
show ip dhcp snooping
```

## Dynamic ARP Inspection (DAI)

### Understanding ARP and Its Risks

The **Address Resolution Protocol (ARP)** maps IP addresses to MAC addresses in a local network. Devices use ARP requests to ask, “Who has this IP address?” and expect a reply containing the MAC address of the target device.

However, ARP is inherently insecure — it trusts any reply it receives. Attackers can exploit this with **ARP spoofing (or poisoning)** by sending forged ARP messages, tricking other devices into associating the attacker’s MAC address with another device’s IP address. This allows interception or redirection of network traffic.

A variation known as **Gratuitous ARP** can also be used in attacks. Normally, Gratuitous ARP is legitimate — devices use it to announce their presence or detect IP conflicts. But attackers can send fake Gratuitous ARPs to poison ARP caches and impersonate other hosts.

---

### Dynamic ARP Inspection (DAI) Logic

**Dynamic ARP Inspection (DAI)** combats ARP-based attacks by validating ARP packets received on untrusted switch ports. It uses two sources of truth:

1. The **DHCP Snooping Binding Table**, which lists legitimate IP–MAC–VLAN–port associations.
2. Optionally, **manually configured ARP Access Control Lists (ACLs)** for static devices.

DAI inspects each incoming ARP packet and verifies:

* Does the source IP–MAC pair match a valid entry?
* Is the interface trusted or untrusted?
* Does the packet rate exceed configured limits?

If an ARP packet fails validation, it is discarded — preventing spoofing or redirection attacks.

---

### Configuring Dynamic ARP Inspection

1. **Enable DAI for specific VLANs:**

   ```
   ip arp inspection vlan <vlan-list>
   ```
2. **(Optional)** Configure trusted ports (e.g., uplinks):

   ```
   interface <type/number>
   ip arp inspection trust
   ```
3. **(Optional)** Set ARP rate limits to protect against floods:

   ```
   interface <type/number>
   ip arp inspection limit rate <number> burst interval <seconds>
   ```

   Disable rate limiting if necessary:

   ```
   ip arp inspection limit rate none
   ```
4. **(Optional)** Enable automatic recovery for err-disabled ports:

   ```
   errdisable recovery cause arp-inspection
   errdisable recovery interval <seconds>
   ```
5. **(Optional)** Validate specific ARP fields (recommended):

   ```
   ip arp inspection validate {src-mac | dst-mac | ip}
   ```

**Verification:**
Use these commands for monitoring:

```
show ip arp inspection
show ip dhcp snooping binding
```

---

## Key Takeaways

* **DHCP Snooping** protects the network from rogue DHCP servers by validating messages and building a trusted binding table.
* **Dynamic ARP Inspection (DAI)** prevents ARP spoofing by cross-checking ARP messages against trusted IP–MAC bindings.
* Both features complement each other — DHCP Snooping provides the data foundation that DAI uses for ARP validation.
* Regularly monitor both features to ensure ongoing protection against spoofing and network compromise.
