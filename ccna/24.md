## OSPF Neighbor Relationships  

Open Shortest Path First (OSPF) is a link-state routing protocol that depends heavily on the correct establishment of **neighbor relationships**. If two routers fail to form or maintain adjacency, OSPF routing will not function properly.  

---

### OSPF Neighbor Requirements  

To successfully establish an OSPF neighbor relationship, routers must meet several conditions.  

| **Requirement** | **Mandatory for OSPF** | **Neighbor Missing If Incorrect** |
|-----------------|-------------------------|----------------------------------|
| Interfaces must be in an **up/up** state | Yes | Yes |
| ACLs must not block OSPF messages | Yes | Yes |
| Interfaces must share the same **subnet** | Yes | Yes |
| Authentication (if configured) must match | Yes | Yes |
| Hello and Dead timers must match | Yes | Yes |
| Router IDs (RIDs) must be unique | Yes | Yes |
| Routers must be in the same **OSPF area** | Yes | Yes |
| OSPF process must be active (not shut down) | Yes | Yes |
| OSPF must be enabled on the interface | Yes | Yes |
| MTU settings should match | Yes | No |
| Network types must match | Yes | No |
| Both interfaces cannot have **priority 0** | Yes | No |

> ✅ *Note:* If any “Yes” value under **Neighbor Missing If Incorrect** is violated, the neighbor will not appear in the `show ip ospf neighbor` output.

---

### Useful Commands for Troubleshooting Neighbor Relationships  

| **Requirement** | **Best Command(s)** |
|------------------|---------------------|
| Hello/Dead timers must match | `show ip ospf interface` |
| Routers must share the same area | `show ip ospf interface brief` |
| RIDs must be unique | `show ip ospf` |
| Authentication must match | `show ip ospf interface` |
| OSPF process must be active | `show ip ospf`, `show ip ospf interface` |

## Issues That Prevent Neighbor Adjacencies  

Even with correct configuration, certain conditions can prevent OSPF neighbors from forming properly.  

---

### Shutting Down the OSPF Process  

To restart the OSPF process manually:  
```
clear ip ospf process
````

To disable or re-enable OSPF globally:

```
shutdown
no shutdown
```

**When OSPF is shut down**, the router:

* Tears down all neighbor relationships.
* Clears the LSDB (Link-State Database).
* Removes all OSPF-learned routes from the routing table.

However, the OSPF configuration remains intact, and all OSPF interfaces are still listed (though shown as *DOWN*) in `show ip ospf interface`.

---

### Shutting Down OSPF on a Specific Interface

To stop or restart OSPF on an individual interface:

```
ip ospf shutdown
no ip ospf shutdown
```

This is similar to the global shutdown command but limited to one interface.

**When used:**

* The router stops sending Hello packets on that interface.
* Existing adjacencies time out and trigger OSPF reconvergence.
* Routes relying on that interface are removed.
* The connected subnet is no longer advertised.

> ⚠️ *Difference from passive interfaces:* Passive interfaces still advertise their subnet; `ip ospf shutdown` completely stops both advertisement and participation.

## Issues That Allow Neighbors but Prevent IP Routes

In some cases, routers successfully form adjacencies but still fail to install routes.

---

### Mismatched MTU Settings

If two routers have different **MTU values**, they may form a neighbor relationship but fail during **database exchange**. They repeatedly transition between intermediate neighbor states (like *EXSTART* or *EXCHANGE*) before dropping the connection and starting over.

---

### Mismatched OSPF Network Types

When neighboring routers use **different network types** (e.g., one uses *broadcast* and the other *point-to-point*), they may reach a *FULL* state, yet the LSAs exchanged are ignored due to mismatched link-type information. The result: routes are learned but not installed in the routing table.

---

### Both Neighbors Using Priority 0

If all routers on a shared network have **priority 0**, none will volunteer as a **Designated Router (DR)**.
In this situation:

* Routers discover each other and reach the **2-Way/DROTHER** state.
* However, the LSDB exchange process halts because there is no DR to coordinate it.
* The result is a stable but incomplete adjacency — routes won’t propagate.

## Route Selection

After adjacencies are established and LSAs are exchanged, OSPF uses various rules to determine which routes to install in the routing table.

---

### Equal-Cost Multipath (ECMP) Routes

If multiple routes to the same destination have **equal cost**, OSPF can install more than one route for load balancing.

* By default, up to **four equal-cost routes** can coexist (`maximum-paths 4`).
* You can adjust this limit using:

  ```
  maximum-paths <number>
  ```
* Cisco IOS typically balances traffic **per destination** by default.

---

### Routes from Competing Sources

A router may learn about the same destination from multiple routing protocols (e.g., OSPF, EIGRP, or BGP). When this happens, the router relies on **Administrative Distance (AD)** to decide which source to trust.

| **Route Source**   | **Administrative Distance (AD)** |
| ------------------ | -------------------------------- |
| Connected          | 0                                |
| Static             | 1                                |
| BGP (External)     | 20                               |
| EIGRP (Internal)   | 90                               |
| OSPF               | 110                              |
| IS-IS              | 115                              |
| RIP                | 120                              |
| EIGRP (External)   | 170                              |
| BGP (Internal)     | 200                              |
| DHCP Default Route | 254                              |
| **Unusable**           | 255                              |

**Tip:** In `show ip route`, the first number in brackets is the AD, and the second number is the route metric.

---

### IP Forwarding with Longest Prefix Match

When multiple routes match a destination IP, the router chooses the one with the **longest prefix** — meaning the most specific subnet.

For example, between `10.0.0.0/8` and `10.1.0.0/16`, traffic for `10.1.1.5` will use the `/16` route because it’s more specific.

To verify, use:

```
show ip route <destination_ip_address>
```

and look for the **“Routing entry for…”** output.
