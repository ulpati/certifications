## Connected and Local IPv6 Routes

Routers automatically generate IPv6 routes based on how IPv6 addresses are configured on their interfaces. These routes fall into three main categories:  
1. **Connected routes** – created for directly attached networks.  
2. **Local routes** – created for each specific IPv6 address assigned to an interface.  
3. **Static or dynamic routes** – added through manual configuration or routing protocols.  

### Rules for Connected and Local Routes

Here are the key behaviors of IPv6 routers regarding connected and local routes:

- When an interface is assigned a unicast IPv6 address using the `ipv6 address` command, the router automatically creates:
  - A **connected route** for the subnet.
  - A **local route** (/128 prefix) for the specific IPv6 address assigned to the interface.
- **Link-local addresses** do not generate any routes in the routing table.
- If an interface goes down, its connected and local routes are automatically removed. When the interface comes back up, the routes are reinstated.

> **Tip:**  
> - Use `show ipv6 route local` to display all local IPv6 routes.  
> - Use `show ipv6 route connected` to display all connected routes.

## Static IPv6 Network Routes

To manually configure a static route in IPv6, use:

```bash
ipv6 route <network>/<prefix-length> <outgoing-interface> <next-hop IPv6 address>
````

This command tells the router how to reach a specific network. However, the behavior varies slightly depending on the interface type.

| Forwarding Instruction | Serial | Ethernet |
| ---------------------- | :----: | :------: |
| Interface only         |  ✅ Yes |   ❌ No*  |
| GUA/ULA only           |  ✅ Yes |   ✅ Yes  |
| Interface + GUA/ULA    |  ✅ Yes |   ✅ Yes  |
| Interface + LLA        |  ✅ Yes |   ✅ Yes  |
| LLA only               |  ❌ No  |   ❌ No   |

*You can technically configure an Ethernet interface without a next-hop, but the route will not forward packets correctly.

To verify static routes, use:

```bash
show ipv6 route static
```

## Static Default, Host, and Floating Static Routes

### Static IPv6 Default Routes

A default route forwards packets when no more specific route matches the destination.
To configure one:

```bash
ipv6 route ::/0 <outgoing-interface> <next-hop IPv6 address>
```

This is equivalent to IPv4’s `0.0.0.0/0`.

---

### Static IPv6 Host Routes

Host routes work similarly to network routes but match only a single IPv6 address.
To configure one, specify a `/128` prefix length:

```bash
ipv6 route <IPv6-address>/128 <outgoing-interface> <next-hop>
```

This ensures the route targets exactly one host.

---

### Floating Static IPv6 Routes

Floating static routes act as **backup routes**, activated only when the primary route becomes unavailable.
You can configure one using an **Administrative Distance (AD)** higher than that of the primary route:

```bash
ipv6 route <network>/<prefix-length> <outgoing-interface> <AD>
```

When the preferred route fails, the floating route automatically takes over.

## Troubleshooting Static IPv6 Routes

### When a Static Route Appears but Doesn’t Work

If your static route shows up in the routing table but fails to forward traffic correctly, check the following:

#### Prefix and Length

* Verify the `ipv6 route` command references the correct **network prefix** and **prefix length**.

#### Next-Hop Link-Local Address (LLA)

* Ensure both the **next-hop LLA** and the **outgoing interface** are specified.
* Confirm the interface is the correct one for the connected topology.
* Make sure the configured LLA truly belongs to the neighbor router on the same link.

#### Next-Hop GUA/ULA Only

* Check that the next-hop address corresponds to the neighbor’s **interface address** on the same link.
* Confirm that the local router has a valid route to reach that next-hop (usually via a connected route).

#### Outgoing Interface Only

* Make sure the outgoing interface is a **serial interface** (Ethernet-only configurations without a next-hop will fail).
* Double-check that the interface is indeed the one connecting to the correct neighbor.

---

### When a Static Route Doesn’t Appear in the Table

If the route doesn’t show up at all, even though the syntax is correct, consider the following checks:

* The **outgoing interface** must be **up/up** (operational).
* If you use a next-hop **GUA/ULA**, the router must already have a route to reach that address.
* If another route with the same prefix exists, your static route must have a **lower Administrative Distance** to override it.

## Summary

IPv6 routing configuration builds upon familiar IPv4 principles but introduces additional flexibility through **link-local addressing**, **multiple route sources**, and **enhanced static route validation**. Understanding how routers build connected and local routes — and how to troubleshoot static routes — is critical for ensuring reliable IPv6 connectivity.
