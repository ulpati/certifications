## Configuring Switch Interface Speed and Duplex

Switch interfaces that use **fiber cabling** typically require no manual configuration. However, **UTP cabling** supports various speeds and duplex modes, which may require configuration or negotiation.

---

### IEEE Autonegotiation Concepts

**Autonegotiation** allows connected devices to automatically agree on the best possible speed and duplex settings without manual configuration.  
When both devices support full duplex, autonegotiation will always select it as the preferred mode.

#### How Autonegotiation Works
Devices exchange messages called **Fast Link Pulses (FLPs)** before establishing a connection. These pulses work through out-of-band signaling, independent of Ethernet frame transmission standards.

Steps:
1. Both devices send FLP messages that list supported speeds and duplex modes.  
2. Each device identifies the **highest common speed** and the **best duplex option**.  
3. The link is then established using those settings.

#### When Only One Device Uses Autonegotiation
If only one side of the link has autonegotiation enabled, the IEEE standard defines a behavior called **parallel detection**:

- **Speed:** Determined by analyzing the signal from the other device.  
- **Duplex:** Defaults to **half-duplex** for 10/100 Mbps and **full-duplex** for 1 Gbps or faster.

#### Autonegotiation and LAN Hubs
LAN hubs neither generate nor forward FLP messages. Therefore, devices connected through hubs cannot perform autonegotiation and must rely on manual configuration or default values.

---

### Configuring Autonegotiation, Speed, and Duplex

#### Using Autonegotiation on Cisco Switches
By default, Cisco switches use autonegotiation. To explicitly enable it:

```
configure terminal
interface <interface>
speed auto
duplex auto
```

These settings do not appear in the `show running-config` output because they are defaults.

To check current settings: `show interfaces status`

| Port | Name | Status | VLAN | Duplex | Speed | Type |
| ---- | ---- | ------ | ---- | ------ | ----- | ---- |

- A value marked with an “a” (e.g., a-full, a-100) indicates autonegotiated settings.
- auto means the interface will attempt negotiation once the physical link is active.

You can also use: `show interfaces <interface>`
This command provides detailed interface statistics but less information about negotiation.

----

#### Setting Speed and Duplex Manually

To manually configure speed and duplex:
```
configure terminal
interface <interface>
speed <10|100|1000|...>
duplex <half|full>
```

⚠️ Both ends of the link must be configured identically to prevent mismatches.

---

### Using Auto-MDIX on Cisco Switches

**Auto-MDIX** (Automatic Medium-Dependent Interface Crossover) allows a switch to automatically detect and correct cabling pinout issues (straight-through vs crossover).

- **Enable Auto-MDIX:** `mdix auto`
- **Disable Auto-MDIX:** `no mdix auto`

Auto-MDIX works even if enabled on only one side of the connection and is on by default, so it does not appear in the configuration file.

## Managing Switch Interface Configuration

### The MOTD, Description and Interface Range Commands

Use the `bannert motd` command to configure a Message of the Day (MOTD) banner that will be displayed every time someone logs into the switch.
```
banner motd "message"
```

Use the `description` command to label interfaces with helpful notes:
```
interface <interface>
description <text>
```

To apply a command to multiple interfaces at once:
```
configure terminal
interface range g1/1-5
<command>
```

---

### Administratively Controlling Interface State

To disable or enable an interface manually:
```
shutdown
no shutdown
```

- When disabled, `show interfaces status` displays **disabled**.
- `show interfaces <interface>` also shows **administratively down**.

---

### Removing Configuration with the `no` Command

You can revert a command to its default setting using the `no` form:
```
speed 100
no speed    # Reverts to 'speed auto'

duplex half
no duplex   # Reverts to 'duplex auto'
```

To view all settings, including defaults: `show running-config all`

⚠️ This produces a long output — use with caution.

To reset an entire interface: `default interface <interface>`

## Analyzing Switch Interface Status and Statistics

### Interface Status Codes

Cisco switches display interface status using two parameters — **line status (Layer 1)** **and protocol status (Layer 2)**.
Combined, these describe the current operational state of the interface.

`show interfaces` and `show interfaces description` display both; `show interfaces status` uses a single simplified code.

| Line Status           | Protocol Status     | Interface Status | Common Cause                                        |
| --------------------- | ------------------- | ---------------- | --------------------------------------------------- |
| administratively down | down                | disabled         | The `shutdown` command is active                    |
| down                  | down                | notconnect       | Cable issues, speed mismatch, or device powered off |
| up                    | down                | notconnect       | Rare on LAN ports                                   |
| down                  | down (err-disabled) | err-disabled     | Port security or similar feature disabled the port  |
| up                    | up                  | connected        | Interface is operating normally                     |

---

### Duplex Mismatch Issues

A **duplex mismatch** occurs when one end uses **full-duplex** and the other uses **half-duplex**.
The link appears up/up, but the half-duplex device experiences collisions and retransmissions, leading to poor performance.

Example:
If Switch A uses **parallel detection** and Switch B is manually set to **100 Mbps full-duplex**, the mismatch will occur.

---

### Common Layer 1 Problems on Working Interfaces

You can view detailed interface statistics with: `show interfaces <interface>`

Key counters include:
- **Runts**: Frames smaller than 64 bytes, often due to collisions.
- **Giants**: Frames exceeding 1518 bytes (default MTU limit).
- **Input Errors**: Aggregate of runts, giants, CRC errors, and others.
- **CRC Errors**: Frames failing Frame Check Sequence (FCS) validation, often from collisions.
- **Frame Errors**: Malformed frames, possibly with partial bytes.
- **Packets Output**: Number of frames sent from the interface.
- **Output Errors**: Frames that failed to transmit successfully.
- **Collisions**: Total number of collisions during frame transmission.
- **Late Collisions**: Collisions detected after the first 64 bytes of transmission — often a sign of duplex mismatch.
