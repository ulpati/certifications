# Chapter 9 - Spanning Tree Protocol Concepts
> **Source:** Adapted from *CCNA 200-301 Volume 1* by Wendell Odom

The **Spanning Tree Protocol (STP)** is a fundamental technology that allows Ethernet LANs to include redundant links without causing network loops. Redundancy is vital for reliability — if a link or even an entire switch fails, traffic can continue flowing through alternative paths. Without STP, however, these redundant paths could cause severe issues like looping frames, broadcast storms, and MAC table instability.  
Over time, STP evolved into **Rapid Spanning Tree Protocol (RSTP)**, which improves convergence times while maintaining the same core logic.

---

## Understanding STP and RSTP

### Why Spanning Tree Is Needed

In a switched LAN, redundant links without STP or RSTP would create endless loops where Ethernet frames circulate indefinitely.  
To prevent this, STP strategically **blocks certain ports**, ensuring only one active logical path exists between any two devices.

STP and RSTP have two main goals:
- All devices within a VLAN should be able to communicate with each other.
- Frames must have a finite lifetime and never loop endlessly through the network.

When a port is in the **forwarding state**, it sends and receives normal user traffic.  
When a port is in the **blocking state**, it ignores data frames and only processes STP or RSTP messages.

---

### Problems Caused by Loops

A single looping frame can trigger a **broadcast storm**, where endless copies of the same frame circulate throughout the LAN. This overwhelms links, slows down devices, and disrupts normal operations. Loops can also lead to:
- **MAC table instability** – switches repeatedly update MAC entries incorrectly.
- **Multiple frame copies** – the destination device receives duplicates of the same frame.

| Problem | Description |
|----------|--------------|
| **Broadcast storms** | Repeated forwarding of the same frame across links, consuming bandwidth and CPU resources. |
| **MAC table instability** | Constantly changing MAC address table entries due to looping frames. |
| **Multiple frame transmission** | Delivery of multiple copies of a frame to the same host, causing confusion and errors. |

---

## What Spanning Tree Does

STP and RSTP prevent these issues by assigning every switch port one of two logical states:
- **Forwarding** – port actively forwards and receives frames.
- **Blocking** – port discards all user frames but still exchanges STP/RSTP messages.

The process of determining which ports should forward and which should block is called **STP convergence**.

---

## How STP Works

STP/RSTP uses a consistent algorithm based on several key decisions:

1. **Elect the Root Switch** – all active interfaces on the root switch go into the forwarding state.  
2. **Select the Root Port (RP)** – each non-root switch chooses one port with the lowest cost path to the root switch.  
3. **Select the Designated Port (DP)** – for every LAN segment, the switch with the lowest root cost becomes the designated switch for that segment.

All other ports remain **blocked** to avoid loops.

| Port Characterization | State | Description |
|------------------------|--------|--------------|
| All ports on the root switch | Forwarding | The root switch is always the designated switch for all connected segments. |
| Root port on non-root switches | Forwarding | The port with the lowest cost path to the root switch. |
| Designated ports on LAN segments | Forwarding | The switch forwarding the best (lowest-cost) BPDU to the segment. |
| All other operational ports | Blocking | Not used for forwarding or receiving data frames. |

---

### Bridge ID and Hello BPDUs

Each switch has a unique **Bridge ID (BID)**, made of:
- **16-bit priority field**
- **48-bit system ID**, based on the switch’s MAC address.

Switches use **Bridge Protocol Data Units (BPDUs)** to exchange STP information. The most common BPDU is the **Hello BPDU**, which includes:
- The current root bridge ID  
- The sender’s bridge ID  
- The sender’s root cost  
- Timer values (Hello, MaxAge, Forward Delay)

---

### Electing the Root Switch

Root election is based on the lowest **Bridge ID**. The switch with the lowest priority value wins; if tied, the lowest MAC address is used as a tiebreaker.

Initially, every switch advertises itself as root. When a switch receives a BPDU with a better (lower) BID, it stops claiming to be root and forwards the superior BPDU instead. Eventually, all switches agree on one **root switch**.

---

### Selecting the Root and Designated Ports

Each non-root switch calculates the cost of paths to the root and picks its **Root Port** (RP) — the port providing the lowest cumulative cost.  
If two paths have equal cost, tiebreakers are:
1. Lowest neighbor bridge ID  
2. Lowest neighbor port priority  
3. Lowest neighbor port number  

On each LAN segment, the switch with the lowest root cost becomes the **Designated Switch**, and its port becomes the **Designated Port (DP)**.

---

### Adjusting STP Topology

While STP automatically determines roles and states, network engineers can manually influence topology by:
- Modifying the switch **Bridge ID (priority)**  
- Adjusting **port costs**

---

## STP Operation and Convergence

### Stable STP Operations

When the network is stable:
1. The root sends **Hello BPDUs** every two seconds out all forwarding ports.  
2. Non-root switches receive and forward them through their designated ports after updating relevant fields.  
3. This process repeats continuously until topology changes occur.

---

### STP Timers

| Timer | Default | Description |
|--------|----------|-------------|
| **Hello** | 2 seconds | Time between Hello BPDUs from the root switch. |
| **MaxAge** | 10 × Hello | Time a switch waits before deciding the root is unreachable. |
| **Forward Delay** | 15 seconds | Time spent in listening and learning states before forwarding begins. |

---

### Interface States

When a port transitions from **blocking** to **forwarding**, it must pass through two temporary states:
- **Listening** – processes BPDUs and removes stale MAC entries.  
- **Learning** – begins learning MAC addresses but doesn’t forward frames yet.  

Each state lasts for the duration of the **Forward Delay** timer.

---

## Rapid Spanning Tree Protocol (RSTP)

RSTP improves upon STP with faster convergence and additional mechanisms for instant recovery.

| Function | STP Role | RSTP Role |
|-----------|-----------|-----------|
| Best path to root | Root Port | Root Port |
| Backup for root port | — | Alternate Port |
| Forwards to collision domain | Designated Port | Designated Port |
| Backup for designated port | — | Backup Port |
| Non-operational | Disabled | Discarding |

RSTP allows immediate failover when a root or designated port fails by promoting alternate or backup ports without waiting for timers to expire.

---

### RSTP Port Types

- **Point-to-Point** – connects switches directly.  
- **Edge Port** – connects to end devices, skipping normal STP delays.  
- **Shared Port** – connects via a hub.

---

## Optional STP Features

### EtherChannel
Combines multiple links into a single logical interface. STP treats it as one port — if one link fails, the EtherChannel stays active.

### PortFast
Allows access ports to transition directly to forwarding state without waiting for STP timers.

### BPDU Guard
Disables a PortFast-enabled port if it receives any BPDUs, protecting the network from accidental loops.

### BPDU Filter
Prevents STP from running on specific ports. It can either disable STP entirely or temporarily suppress BPDUs on PortFast ports.

### Root Guard
Prevents new root elections on specific ports by disabling them (in a “root inconsistent” state) if a superior BPDU is received.

### Loop Guard
Protects against unidirectional link failures by preventing alternate or root ports from becoming designated ports.
