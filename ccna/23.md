## OSPF Network Types  

Different OSPF network types determine how routers form neighbor relationships and whether they elect Designated Routers (DR) and Backup Designated Routers (BDR).  

| **Network Type** | **Discovers Neighbors Automatically** | **Uses DR/BDR** |
|------------------|---------------------------------------|----------------|
| Broadcast        | Yes                                   | Yes            |
| Point-to-Point   | Yes                                   | No             |

---

### The OSPF Broadcast Network Type  

By default, OSPF treats Ethernet interfaces as **broadcast networks**. This allows routers on the same subnet to automatically discover neighbors and elect DR/BDR routers.  

To explicitly configure a broadcast network type:  
```
ip ospf network broadcast
```

#### Influencing DR/BDR Election

Once elected, DRs and BDRs remain in their roles unless one fails. New routers with higher priority values will **not preempt** an existing DR or BDR.

**Election rules (in order of priority):**
- **Highest OSPF interface priority** – Range: 0–255 (a value of `0` prevents the router from becoming DR/BDR).
- **Highest Router ID (RID)** – Used as a tiebreaker if priorities match.

To configure OSPF interface priority: `ip ospf priority <number>`

**Tip**: Unlike Spanning Tree Protocol (STP), OSPF uses highest-is-best logic and does not support preemption. This means once a DR is chosen, it stays in place until it goes offline.

---

### The OSPF Point-to-Point Network Type

On **serial interfaces**, OSPF defaults to the point-to-point network type: `ip ospf network point-to-point`

Because these links connect only two devices, electing a DR/BDR offers no benefit and can slightly delay convergence. Using the **point-to-point** type ensures faster recovery and simpler neighbor management.

This setting can also be used on **Ethernet WAN links** that behave like point-to-point connections.

## Additional Optional OSPFv2 Features

Beyond basic setup, OSPF includes several optional features that improve performance, flexibility, and control.

---

### OSPF Passive Interfaces

When an interface connects to a network segment with **no other OSPF routers**, sending Hello packets wastes bandwidth. Setting the interface as **passive** prevents OSPF from forming neighbor relationships on that link, while still advertising the subnet to the routing domain.

**Effects of a Passive Interface:**
- OSPF continues to advertise the connected subnet.
- OSPF stops sending or processing Hello packets on that interface.

**Configuration examples:**
`passive-interface <type_number>`

or globally
```
passive-interface default
no passive-interface <type_number>
```

---

### OSPF Default Routes

Routers connected to the Internet often advertise a **default route (0.0.0.0/0)** to internal routers.

Steps:
1. Configure a static default route pointing to the ISP: `ip route 0.0.0.0 0.0.0.0 <next_hop>`
2. Advertise it through OSPF: `default-information originate`

To always advertise a default route (even if one doesn’t currently exist): default-information originate always

### OSPF Metrics (Cost)

OSPF uses an interface **cost** to determine the preferred path. Lower costs are more desirable.

**Setting Cost Directly:** `ip ospf cost <number>` 

**Calculating Cost Automatically**

If not manually configured, the cost is calculated using this formula: `cost = reference_bandwidth / interface_bandwidth`

You can influence the cost calculation by changing:
- **Interface bandwidth** (in Kbps): `bandwidth <speed>`
- **Reference bandwidth (in Mbps):** `auto-cost reference-bandwidth <ref-bw>`

Adjusting the reference bandwidth is helpful in modern high-speed networks (e.g., Gigabit or 10G Ethernet) to ensure accurate metric comparison.

---

### OSPF Hello and Dead Intervals

Routers maintain OSPF neighbor relationships by exchanging Hello packets. The **Hello interval** controls how often Hellos are sent, while the **Dead interval** determines how long a router waits before declaring a neighbor down.

**Configuration:**
```
ip ospf hello-interval <seconds>
ip ospf dead-interval <seconds>
```

**Best Practices & Warnings:**
- Maintain a **4:1 ratio** between Dead and Hello timers (e.g., 40s Dead, 10s Hello).
- Neighboring routers must use **identical timer settings** to form adjacencies.
- Never set the Dead interval lower than the Hello interval — doing so will cause the neighbor relationship to repeatedly fail and recover.
