## Understanding Secure Wireless Connections

The **802.11 standard** provides a set of security mechanisms designed to establish **trust, privacy, and data integrity** in wireless communication. These mechanisms form the foundation of secure Wi-Fi environments and are essential for protecting users and networks from unauthorized access.

---

## Wireless Client Authentication Methods

### Open Authentication

**Open authentication** provides unrestricted access to a WLAN. The only step required for a device is to send an 802.11 authentication request before it can associate with an access point (AP). No additional credentials are needed.  
Its sole function is to verify that the device uses valid 802.11 protocols — user authentication, if required, is handled by other security layers.

---

### WEP (Wired Equivalent Privacy)

**WEP** uses the **RC4 cipher algorithm** to encrypt wireless frames, aiming to provide data privacy similar to wired networks. Both sender and receiver must share an identical **WEP key** to encrypt and decrypt data successfully.

This method is referred to as a **shared-key system**, as all devices must share the same key beforehand. The AP can challenge a client’s knowledge of this key through a **random challenge phrase** test, ensuring both sides are using the same secret.

WEP supports **40-bit or 104-bit keys** (10 or 26 hexadecimal digits). However, both its encryption and shared-key authentication are now considered **insecure and obsolete**.

---

### 802.1X and EAP (Extensible Authentication Protocol)

**EAP** provides a flexible authentication framework rather than a single authentication method. It integrates seamlessly with **IEEE 802.1X**, which restricts network access until a device is properly authenticated.

In this setup:
- The **Supplicant** is the client device requesting access.
- The **Authenticator** is the network device (often a WLC) controlling access.
- The **Authentication Server (AS)** validates credentials, typically through a **RADIUS server**.

With 802.1X, clients first associate with the AP using open authentication, then complete the authentication process via the AS.

#### LEAP (Lightweight EAP)
A Cisco-proprietary method where users authenticate using a **username and password**. Though it attempted to fix WEP’s weaknesses with dynamic keying, LEAP was later found to be insecure and is now deprecated.

#### EAP-FAST (Flexible Authentication via Secure Tunneling)
Developed by Cisco to improve LEAP, **EAP-FAST** uses a **Protected Access Credential (PAC)** for mutual authentication:
1. **Phase 0:** The PAC is generated and installed.
2. **Phase 1:** The client and server authenticate each other and establish a **TLS tunnel**.
3. **Phase 2:** User authentication occurs securely inside that tunnel.

#### PEAP (Protected EAP)
**PEAP** builds a secure **TLS tunnel** where the authentication server presents a **digital certificate** to the client. Inside this tunnel, the client authenticates using:
- **MSCHAPv2** (Microsoft Challenge Authentication Protocol v2)
- **GTC** (Generic Token Card) for one-time passwords.

#### EAP-TLS
The most secure form of EAP, **EAP-TLS** uses digital certificates on both the client and the server. After mutual authentication, they establish a **TLS tunnel** for encryption key exchange. This method is considered the **gold standard** for wireless authentication.

## Wireless Privacy and Data Integrity

### TKIP (Temporal Key Integrity Protocol)
**TKIP** improved upon WEP by introducing:
- **MIC (Message Integrity Check)** to detect tampering.
- **Timestamps** to prevent replay attacks.
- **MAC address verification** for sender validation.
- **Sequence counters** to avoid frame duplication.
- **Key mixing algorithms** to create unique keys per frame.
- **48-bit IVs** for enhanced randomness.

> ⚠️ **TKIP is now deprecated** and should not be used.

---

### CCMP (Counter/CBC-MAC Protocol)
**CCMP** relies on **AES encryption** with two main algorithms:
- **AES Counter Mode** for encryption  
- **CBC-MAC** for message integrity

CCMP provides strong data confidentiality and integrity and is widely implemented in modern Wi-Fi networks. Both clients and APs must support AES in hardware to use CCMP effectively.

---

### GCMP (Galois/Counter Mode Protocol)
**GCMP** enhances performance and security compared to CCMP by using:
- **AES Counter Mode** for encryption  
- **GMAC** for authentication and integrity checks

This protocol is the modern standard for high-performance, secure WLANs.

## WPA, WPA2, and WPA3 Security Standards

The **Wi-Fi Alliance** established the **Wi-Fi Protected Access (WPA)** standards to simplify the implementation of authentication and encryption across wireless networks.

| Feature | WPA | WPA2 | WPA3 |
|----------|------|-------|-------|
| Pre-Shared Key (PSK) Authentication | ✅ | ✅ | ✅ |
| 802.1X Authentication | ✅ | ✅ | ✅ |
| TKIP Encryption | ✅ | ❌ | ❌ |
| AES + CCMP Encryption | ✅ | ✅ | ❌ |
| AES + GCMP Encryption | ❌ | ❌ | ✅ |

**WPA3** introduces significant improvements such as:
- **Simultaneous Authentication of Equals (SAE)**  
- **Forward Secrecy** (protects past sessions if keys are compromised)  
- **Protected Management Frames (PMF)**  

---

### Personal Mode vs. Enterprise Mode

All WPA versions support two authentication models:

- **Personal Mode (PSK):** A shared key is manually configured on all clients and APs. This key is never transmitted; instead, a **four-way handshake** generates temporary encryption keys.  
  WPA3 enhances this process using **SAE**, preventing offline password-cracking attacks.

- **Enterprise Mode (802.1X):** Authentication is handled via a RADIUS server, providing centralized control and scalability for large deployments.
