## Understanding SNMP (Simple Network Management Protocol)

The **Simple Network Management Protocol (SNMP)** is a cornerstone of network monitoring and management. It allows administrators to collect information from network devices, modify configurations, and receive alerts about system events.

Today, the two main versions in use are **SNMPv2c** and **SNMPv3**.

---

### How SNMP Works

SNMP operates through communication between **SNMP managers** and **SNMP agents**:

- The **SNMP Manager** (often part of a Network Management System, or NMS) runs on a server or workstation.  
- The **SNMP Agent** is built into each network device and keeps track of internal variables—configuration details, operational status, and performance counters.

Each agent stores this information in a structured database known as the **Management Information Base (MIB)**. The SNMP manager queries or updates the MIB to monitor and control devices.

---

### Reading and Writing SNMP Variables: Get and Set

The SNMP manager uses two core message types:

- **Get Requests** – retrieve information from the agent.  
- **Set Requests** – modify specific variables on the device.

SNMPv1 introduced two forms of Get requests:
- **Get** – retrieves specific variable values.
- **GetNext** – retrieves the next variable in sequence, allowing for easier MIB traversal.

SNMPv2 improved this process by introducing the **GetBulk** request, enabling the retrieval of multiple variables in one message—saving bandwidth and reducing overhead.

---

### SNMP Notifications: Traps and Informs

SNMP isn’t only about pulling data—it also allows agents to **push** information to managers.

Agents can send **notifications** when certain events occur, using one of two message types:
- **Trap** – a one-way alert message sent by the agent; no confirmation is expected.  
- **Inform** – similar to Trap, but requires an acknowledgment from the NMS. If no confirmation arrives, the agent resends the message.

Traps are faster but unreliable; Informs are slower but more reliable thanks to acknowledgment and retransmission.

---

### The Management Information Base (MIB)

The **MIB** acts like a directory of all manageable variables within a device.  
Each variable is identified by an **Object Identifier (OID)** arranged hierarchically, forming a tree-like structure.

For an SNMP manager to successfully interact with agents, it must use the same MIB definitions that the agents support.  
Vendors often include standard and proprietary MIBs in their devices, and management systems typically preload common ones.

---

### Securing SNMP

Security is critical in SNMP communications because they can reveal sensitive configuration data.

#### **SNMPv1 and SNMPv2c Security**
Earlier versions used *community strings*—essentially passwords sent in clear text.  
- A **read-only** community allows monitoring (Get only).  
- A **read-write** community allows full access (Get and Set).

Because these are unencrypted, using **Access Control Lists (ACLs)** to restrict communication to trusted NMS hosts is strongly recommended.

#### **SNMPv3 Security Enhancements**
SNMPv3 introduced modern security mechanisms:
- **Message Integrity** – ensures messages aren’t altered during transmission.  
- **Authentication** – verifies the identity of the sender using secure hashing methods.  
- **Encryption (Privacy)** – protects data from being read if intercepted.

Together, these features make SNMPv3 the preferred and most secure version today.

## FTP and TFTP in Network Management

Both **File Transfer Protocol (FTP)** and **Trivial File Transfer Protocol (TFTP)** are used to move files between devices and servers, such as **Cisco IOS images** and configuration backups.

They follow a **client–server model**: the client initiates the connection, and the server provides or accepts files.

---

### Managing Cisco IOS Images with FTP and TFTP

Cisco routers use an **IOS file system (IFS)** to manage files like the operating system image.  
When upgrading IOS:
1. Download the desired image from Cisco (via HTTP or FTP).  
2. Place the image on a reachable FTP/TFTP server or USB drive.  
3. Use the `copy` command to transfer it to the router’s flash memory:  
```

copy <source_path> <destination_path>

````

During the process, the router will prompt for:
- Server IP or hostname  
- Filename  
- Storage verification (enough space available)  
- Confirmation to overwrite existing files

After copying, IOS automatically verifies the file checksum to ensure integrity.

---

### Exploring the IOS File System

The **IOS File System (IFS)** organizes storage into logical structures, similar to traditional operating systems.

- **Flash memory** is non-volatile and retains data even when powered off.  
- **NVRAM** holds startup configurations.  
- **Network** and **Opaque** types represent logical or remote file systems.

Useful commands:
```bash
show file systems
show flash:
dir flash:
cd <directory>
pwd
````

---

### Verifying IOS Image Integrity (MD5/SHA512)

To ensure the downloaded IOS image is genuine, Cisco provides **hash values** (MD5 or SHA512).
You can verify integrity using:

```bash
verify /md5 flash:<filename>
verify /sha512 flash:<filename>
```

If the computed hash matches Cisco’s published hash, the file is authentic.

---

### File Transfer Methods

| Method   | Full Name                      | Encrypted |
| -------- | ------------------------------ | --------- |
| **TFTP** | Trivial File Transfer Protocol | ❌ No      |
| **FTP**  | File Transfer Protocol         | ❌ No      |
| **SCP**  | Secure Copy Protocol           | ✅ Yes     |

**Example FTP Copy Command:**

```bash
copy ftp://<username>:<password>@<server_ip>/<file> flash:
```

You can also predefine credentials:

```bash
ip ftp username <username>
ip ftp password <password>
```

Then use a simplified copy command:

```bash
copy ftp://<server_ip>/<file> flash:
```

## Understanding the FTP and TFTP Protocols

### FTP Basics

**FTP** uses **TCP ports 21 (control)** and **20 (data)**, ensuring reliable, ordered delivery.

FTP supports:

* Navigating directories
* Listing, creating, and deleting files
* Uploading (PUT) and downloading (GET) files

---

### FTP Connection Modes

FTP operates in two modes:

#### **Active Mode**

* The client listens on a random port and tells the server where to connect using the `PORT` command.
* The **server initiates** the data connection back to the client.

This mode can cause issues with firewalls, as inbound connections from the server might be blocked.

#### **Passive Mode**

* The client sends a `PASV` command.
* The **server listens** on a random port and tells the client which port to use.
* The **client initiates** both control and data connections.

Passive mode works better through firewalls since all connections originate from the client.

---

### TFTP Basics

**Trivial File Transfer Protocol (TFTP)** is a simplified alternative to FTP.

* Uses **UDP port 69**
* Lacks authentication, encryption, or directory control
* Only supports **Get** and **Put** operations
* Includes basic checksum validation for integrity

Because TFTP is lightweight and insecure, it’s typically used in **controlled environments** for quick file transfers—such as bootstrapping network devices or transferring IOS images.
