## IP Routing

### Understanding the IPv4 Routing Process

When a host creates an IP packet, the routing process determines how that packet reaches its destination. The steps are as follows:

1. **If the destination is on the same subnet:**
   - The device looks up the destination’s MAC address using the **ARP table** or sends an **ARP request** to learn it.
   - The packet is encapsulated into a data-link frame, using the destination host’s MAC address as the destination address.

2. **If the destination is on a different subnet:**
   - The device finds the **default gateway’s** MAC address (again, via ARP if not already known).
   - The IP packet is then encapsulated in a frame addressed to the gateway’s MAC address.

---

### Router Routing Logic

When a router receives a data-link frame, it processes it as follows:

1. **Frame Validation:**  
   The router checks for errors using the Frame Check Sequence (FCS). If errors are found, the frame is discarded.

2. **Frame Destination Check:**  
   The router only processes frames addressed to its own MAC address (or to a broadcast/multicast address).

3. **De-encapsulation:**  
   The router removes the data-link header and trailer, exposing the IP packet.

4. **Routing Decision:**  
   It compares the packet’s destination IP address with its **routing table**, identifies the **best matching route**, and determines the **outgoing interface** and **next-hop router** (if applicable).

5. **Re-encapsulation and Forwarding:**  
   The packet is re-encapsulated into a new data-link frame suitable for the outgoing interface. If necessary, ARP is used again to discover the next device’s MAC address.

6. **Transmission:**  
   The router sends the newly created frame out through the selected interface.

## Configuring IP Addresses and Connected Routes

Routers learn routes in three primary ways:

- **Connected routes** – automatically added when an interface is configured with an IP address using the `ip address` command.  
- **Static routes** – manually added using the `ip route` command.  
- **Dynamic routing protocols** – learned automatically through configured routing protocols.

Use the command `show ip route` to view all available routes.  
Each interface configured with an IP address also generates a **local route**, a special entry representing that single IP address as a /32 (host) route.

---

### Connected Routes and the `ip address` Command

A Cisco router automatically adds a **connected route** to its routing table for each active interface that:

- Is operational (line and protocol shows *up/up*)
- Has an IP address assigned via the `ip address` interface subcommand.

This allows the router to know about directly connected subnets without manual configuration.

---

### Common Mistakes When Assigning IP Addresses

Some typical errors to avoid include:

1. **Using Reserved Addresses:**  
   IOS will reject IP addresses that correspond to the subnet ID or broadcast address.

2. **Incorrect Default Gateway:**  
   Misconfiguring a router’s IP address so that it doesn’t match the default gateway configured on hosts.

3. **Duplicate Subnets:**  
   Assigning the same subnet to multiple interfaces on the same router — only the first configuration will be accepted.

---

### Viewing and Managing the ARP Table

The **ARP table** shows the mapping between IP addresses and MAC addresses for devices on the same subnet.

- View the ARP table: `show ip arp`
- Clear a specific entry: `clear ip arp <ip_address>`

## Configuring Static Routes

Static routes are manually defined network paths that guide packets toward their destination.

### Static Network Routes

A static route identifies a destination **network or subnet** and specifies how to reach it — either via an outgoing interface or a next-hop IP address (or both).

Command syntax: `ip route <destination_network> <subnet_mask> <next-hop_ip> [permanent]`

Adding the permanent keyword ensures that the route remains in the routing table, even if the outgoing interface is down.

---

#### Verifying Static Routes

To display static routes: `show ip route static`

If an interface goes down, IOS removes the route from the table automatically.

When the interface comes back up, the route is reinstalled.

Keep in mind that with only static routes, all directions of traffic must be manually defined on each router.

---

#### Ethernet Outgoing Interfaces and Proxy ARP

**Proxy ARP** allows a router to respond to ARP requests on behalf of another device that resides on a different network segment. This enables devices to communicate across subnets as if they were part of the same local network.

**Proxy ARP process:**
1. A router receives an ARP request on one of its interfaces (for example, Interface X).
The request targets an IP address outside the subnet associated with that interface.
2. The router checks its routing table to determine if it has a valid route to that destination.
If such a route exists and forwarding traffic through that interface will not cause a loop, the router considers acting as a proxy.
3. Acting as a proxy for the target device, the router responds to the ARP request with its own MAC address instead of the real host’s address.
4. The original requester updates its ARP table to associate the target IP with the router’s MAC address.

As a result, it sends packets to the router, which then forwards the traffic to the actual destination based on its routing information.

This mechanism enables seamless communication between devices that are unaware of each other’s subnet boundaries.
It can simplify certain network configurations but should be used carefully, as it may introduce complexity or unintended traffic forwarding in larger or more segmented networks.

---

### Static Default Routes

A **default route** acts as a “catch-all” path for packets that don’t match any other specific route in the routing table.

**Command syntax:** `ip route 0.0.0.0 0.0.0.0 <next-hop_ip>`

This is especially useful for routers connecting to the internet or a central gateway.

---

### Static Host Routes

A **host route** defines a path for a single IP address (using a /32 mask).
This type of route is often used for specific traffic control or troubleshooting.

**Command syntax:** `ip route 0.0.0.0 0.0.0.0 <next-hop_ip>`

This is especially useful for routers connecting to the internet or a central gateway.

---

### Static Host Routes

A **host route** defines a path for a single IP address (using a /32 mask).
This type of route is often used for specific traffic control or troubleshooting.

**Command syntax:** `ip route <host_ip> 255.255.255.255 <next-hop_ip>`

Since routers prefer **longest prefix matches**, a host route will override less specific routes, even if those were learned dynamically.

---

### Floating Static Routes

**Floating static routes** act as **backup routes** that become active only when the primary route fails.
They are configured with a **higher administrative distance (AD)** than the main route, making them less preferred under normal conditions.

**Command syntax:** `ip route <network> <mask> <backup_next-hop_ip> <administrative_distance>`

If the primary route (with a lower administrative distance) disappears, the floating static route automatically takes over until the main path is restored.
