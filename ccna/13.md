## Subnet Mask Conversion

### Three Mask Formats

A subnet mask can be written in three common ways:

- **Binary format:** 32 bits composed of 1s and 0s  
- **Dotted-decimal notation (DDN):** Four decimal numbers separated by dots (e.g., `255.255.255.0`)  
- **Prefix notation:** A slash followed by the number of 1 bits in the mask (e.g., `/24`)  

---

### Converting Between Binary and Prefix Masks

- **Binary → Prefix:**  
  Count the number of `1`s in the binary mask. The total number of 1 bits becomes the prefix length (e.g., 24 ones → `/24`).

- **Prefix → Binary:**  
  Write *P* ones, where *P* is the prefix value, and then fill the remaining bits with zeros to complete a 32-bit mask.

---

### Converting Between Binary and Dotted-Decimal Masks

In **Dotted-Decimal Notation (DDN)**, each octet (8 bits) is represented as a decimal number. There are only nine possible values for a subnet mask octet:

| Binary Octet | Decimal Equivalent | Number of 1 Bits |
|:-------------:|:------------------:|:----------------:|
| 00000000 | 0 | 0 |
| 10000000 | 128 | 1 |
| 11000000 | 192 | 2 |
| 11100000 | 224 | 3 |
| 11110000 | 240 | 4 |
| 11111000 | 248 | 5 |
| 11111100 | 252 | 6 |
| 11111110 | 254 | 7 |
| 11111111 | 255 | 8 |

- **Binary → Decimal:**  
  Divide the 32-bit mask into four groups of 8 bits. For each group, use the table to find its decimal equivalent.

- **Decimal → Binary:**  
  Reverse the process: convert each decimal number in the DDN mask back into its corresponding 8-bit binary form.

---

### Converting Between Prefix and DDN Masks

When converting between **prefix length** and **decimal notation**, it’s easiest to first go through the binary representation.  
For example, `/26` corresponds to `255.255.255.192` because the first 26 bits are ones.

## Identifying Subnet Design Choices Using Masks

### Masks Divide an Address into Two Parts

A subnet mask separates an IP address into two parts:

- **Prefix (Subnet) part:** Identical for all addresses within the same subnet  
- **Host part:** Unique for each device within that subnet  

This division defines which devices can communicate directly within the same local network.

---

### Masks and Classes Divide Addresses into Three Parts

When subnetting a **classful network** (Class A, B, or C), the IP address can be conceptually divided into **three parts**:

1. **Network part:** Defined by the class (A, B, or C)  
2. **Subnet part:** Additional bits borrowed from the host portion  
3. **Host part:** Remaining bits used for individual device addresses  

For example, in a Class B network (`255.255.0.0`) extended with a `/20` mask, 4 bits are borrowed from the host portion to form the subnet part.

---

### Classless vs. Classful Addressing

- **Classless Addressing (CIDR):**  
  The IP address is divided into a **prefix** and **host** part, with no reliance on traditional class boundaries. CIDR enables flexible subnetting and efficient address use.

- **Classful Addressing:**  
  The IP address consists of **network**, **subnet**, and **host** parts. This traditional method follows predefined class rules (A, B, or C).

---

### Calculations Based on IPv4 Address Format

When analyzing or designing subnets, use these formulas:

1. Convert the mask to **prefix format** (`/P`).  
2. Identify **N**, the number of network bits (based on the class).  
3. Calculate **S = P - N**, where S is the number of subnet bits.  
4. Compute **H = 32 - P**, representing the host bits.  
5. Find the number of **usable hosts per subnet**: `2^H - 2`.  
6. Find the number of **available subnets**: `2^S`.  

> ⚠️ The formula for the number of subnets (`2^S`) applies only when all subnets in a network share the same mask.

---

### Masks and CIDR Blocks

In traditional **classful networks**, the network portion was defined by the class (A, B, or C).  
However, **Classless Inter-Domain Routing (CIDR)** introduced the idea of using a **prefix length** instead of a fixed class boundary.  

CIDR allows networks to be aggregated or subdivided more efficiently, conserving IP address space and simplifying routing.
